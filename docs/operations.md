# 运维与资源预算

## 配置

`Options` 可通过 Rust 构造或 HTTP 服务 `--config` JSON 文件设置。未知配置字段拒绝。以下为默认值：

| 字段 | 默认值 |
|---|---:|
| global_memory_bytes | 4 GiB |
| tenant_memory_bytes | 512 MiB |
| tenant_disk_bytes | 100 GiB |
| cache_bytes | 128 MiB |
| memtable_bytes | 16 MiB |
| block_bytes | 16 KiB |
| target_sst_bytes | 16 MiB |
| level_base_bytes | 64 MiB，后续层每层扩大 10 倍 |
| io_workers | 4 |
| max_tenant_requests | 32 |
| max_http_requests | 64，普通执行名额；准入和正文完成后取得 |
| max_http_body_requests | 256，非空正文接收及其预算准备 |
| max_http_admission_requests | 256，等待冷预算锁的独立准入名额，含空正文 |
| max_http_index_requests | 4，独立建索引执行名额 |
| max_http_lifecycle_requests | 4，独立删除租户、close 和配额执行名额 |
| max_http_maintenance_requests | 4，备份、合并、校验、检查点及本地恢复；与建索引共享每租户重任务上限 1 |
| max_http_connections | 1024，仅内置服务监听器 |
| http_write_timeout_ms | 30000，内置监听器写空闲期限 |
| http_header_timeout_ms | 5000，内置 HTTP/1 服务请求头及 keep-alive 等待期限 |
| maintenance_reserve_free_bytes | 64 MiB，复制检查点及本地备份物理空闲余量 |
| max_local_backup_bytes | 1 GiB，每租户本地备份总额，同时不超过租户磁盘配额 |
| idle_seconds | 300 |
| snapshot_seconds | 60 |
| index_build_seconds | 3600，构建快照单独上限 |
| max_snapshots | 256 |
| max_document_bytes | 1 MiB |
| max_batch_operations | 1000 |
| max_batch_bytes | 16 MiB |
| max_read_keys | 1000 |
| max_page_size | 1000 |
| max_scan | 100000 |
| query_ms | 5000 |
| max_response_bytes | 16 MiB |
| max_query_bytes | 64 MiB |
| l0_trigger / l0_stop | 4 / 12 |

文档格式上限 16 MiB、输入批次格式上限 64 MiB、响应上限可配置为 1–64 MiB、展开后的 WAL 原子记录上限 64 MiB；这些是实现边界，调高配额不会绕过。批次可能因覆盖索引扩张而超过 WAL 上限并被整体拒绝。批次数量、读键数和分页大小可调至最多 100000，但仍受字节、扫描、时间及内存预算约束。JSON 深度最多 32、字段/元素数最多 16384、编码键最多 8 KiB。

缓存容量不能直接等同进程 RSS：引擎计入 memtable、块缓存及被引用块、版本目录、事务变更、查询候选和游标的预算；Rust 分配器、网络栈和调用方保留的返回值仍占进程内存。HTTP 请求正文及发送中的响应另计全局预算；JSON 树在解析前按结构估算并同时计入目标租户预算。冷租户恢复、解析与引擎操作在有界阻塞工作池执行。备份校验和恢复暂存实例与在线实例共用该租户内存计数器。部署时应为这些开销预留余量，并以 RSS/cgroup 和引擎预算双重观测。

Store 在全局内存上限内为压力刷盘保护一部分容量：`min(global_memory_bytes / 8, 4 * (max_document_bytes + block_bytes) + 2 MiB)`，默认约 6.06 MiB。普通写入、查询、缓存和备份不能使用这部分容量；实际分配仍计入同一个全局计数器，租户配额仍生效。普通可用容量达到约 7/8 时，后台也会刷盘尚未达到各自 memtable 阈值的租户，合并过程中同样检查此压力。一次只允许一个压力刷盘使用保护容量，竞争者返回 BUSY 并交由后续维护重试；低压力时正常刷盘保持并发。刷盘新建 SST 的初始化可使用保护容量，之后的读取与缓存恢复普通预算。`memory_bytes` 反映实际计费量，未使用的保护容量不显示为已分配内存。此机制不作废长期快照，不突破预算，也不能保证任意大原子记录或持续磁盘故障下都能推进；客户端仍需对明确拒绝的 RESOURCE_EXHAUSTED/BUSY 做有界退避。

租户缓存上限取配置值与租户配额三分之一的较小者。默认配置校验、在线配额调整和从库配额同步使用一致下限：内存须覆盖两倍 memtable 阈值及有效缓存，且不超过全局预算；磁盘至少 1 MiB。默认配置仍要求完整配置缓存可容纳。下限允许启动，不保证任意文档、索引展开或原子帧都可在该配额内执行。在线缩小内存配额前在新预算下试开现有 WAL 和校验数据块，副本先用旧预算刷盘以跟随主库已接受的缩容，并计入尚未释放的租户预留；不能回放时返回 RESOURCE_EXHAUSTED，旧配额继续有效。主库管理和副本配额更新共用该检查。关闭、删除、配额调整和本地恢复发布前会阻止新请求，最多排空一秒；短读重叠不再导致永久 BUSY，超时返回 BUSY 并恢复入口，不作废已有游标或快照。排空等待不持节点角色许可，发布前重新取得并核对角色。长期保留的嵌入式句柄仍须调用方释放。缩容验证会关闭并回放实例；长时间预检不持有节点角色屏障和 slot 锁，本租户的新请求返回 BUSY；发布时重新核对角色和身份。验证及恢复本身可能需要 I/O、时间和额外全局预算，数据块校验会扫描存储，应在停止该租户新流量后进行。元数据发布发生不确定 I/O 错误时，该租户返回 UNAVAILABLE，重新打开 Store 后按持久状态恢复。维护与数据块读取使用有界共享工作池；I/O 按租户轮询分配任务；租户内 WAL/注册发布及 memtable flush 输出优先，前台读取其次，SST 合并读写、校验及备份拷贝使用后台层。最多连续 8 个优先任务后让读取推进，每 8 个前台任务至少给排队后台任务一次机会；单批独立块最多 8 个在途。此调度提供任务级公平，不构成磁盘 IOPS 或带宽的硬 SLA。正常达到 memtable 阈值由后台刷盘；积压到阈值 3 倍时前台尝试刷盘，维护锁忙时立即交还后台，超过 4 倍时拒绝继续增长，避免排在整次合并之后。调度时刷盘优先于同租户合并；已经运行的合并每处理 256 条内部记录检查内存表压力，必要时在同一个维护任务内插入刷盘，再继续合并；不可返回的单次 I/O 和 L0 压力仍可能背压。各层积压按压力选取合并；此策略不提供后台任务并行时的硬延迟隔离。

读 I/O 队列最多排队 4096 项；写入和持久化任务不受读队列水位拒绝，仍由调用侧并发和租户预算约束。未进入队列的 WAL 追加失败不标记 COMMIT_UNKNOWN；已经开始追加或同步失败仍隔离写入。内存不足时按需逐帧淘汰块缓存，保留其余可用帧。组提交在同步期间释放写锁，只发布同步开始前捕获的序号；后续暂存需要下一次同步。刷盘/合并的最终 Manifest 发布由维护锁串行化，文件同步放在写锁外；WAL 轮转在短写锁内切换内存表，注册发布期间允许暂存新事务，但必须等 Manifest 持久化后才可确认这些事务。

v0.3 的 DSL AST 缓存另外计入同一租户/全局内存预算，最多 256 项、4 MiB 保守计费容量；查询目录缓存最多 128 个集合、4 MiB。它们不是预算外的内存，也不是进程 RSS 的硬上限。外部 Arc 持有已淘汰准备语句或执行中的目录引用时，预留量保持到最后引用释放，故总持有量可能高于缓存内条目容量，但不能绕过全局/租户预算。纯 `Prepared::parse` 的分配由嵌入式调用方承担；推荐 `TenantHandle::prepare_dsl` 取得计费准备语句。

DSL 语句最多 64 KiB，参数编码量受 `max_batch_bytes` 限制，展开后的绑定临时内存受 `max_query_bytes` 限制。参数多次引用会累计计费，在克隆前拒绝超额展开。AST 缓存随租户实例关闭/恢复而释放，目录缓存随 DDL 序号失效；普通写入不使语法缓存失效。

磁盘预算包含当前租户目录中的 WAL、SST、构建增量、旧版本及临时输出。普通写入只使用配额的 80%，为维护预留空间。刷盘和合并预留 64 KiB 发布余量后，按 SST 实际写出字节增量申请预算，较大的 Manifest 追加预留，层级提升也计入 Manifest 发布空间。输出不能容纳时清理未发布文件并保留原 Manifest 和数据；旧快照持有的文件仍计入占用。v0.8.1 允许复制回放使用维护预留空间，防止到达前台写入门槛后无法回放删除记录；总配额仍生效。资源不足仍可能拒绝写入，合并无法抢占运行中的 I/O。备份目录单独管理，不包含在在线数据库配额内，需配置外部卷容量或运维保留策略。

v0.10.1 校准磁盘用量时持有维护锁固定文件发布和 WAL 轮转，但不在遍历目录期间持有写锁；最后用短写锁读取当前 WAL 实际长度并发布总量，包含扫描期间完成的提交。空闲检查使用不可变版本预先计算的层大小和 L0 压力；目录全面核对每 5 秒进行一次，刷盘/合并发布后立即核对。每个维护 tick 仍核对活跃 WAL 长度，及时释放每次提交的保守磁盘预留；占用达到配额 60% 时每 tick 全面核对，以免旧快照释放后的空间回收等待 5 秒。低占用时，外部文件变化或旧 SST 释放最多到下一次全面核对才反映在统计中。维护调度 tick 仍为 100 ms；队列拥堵或长任务会延后实际执行，此频率不是完成期限。持久化顺序和写入配额门槛保持不变。

## 生命周期

新租户先在 staging 中创建，再借助已有生命周期 journal 发布目录和注册表。创建返回 I/O 错误可能已有持久意图，不应无限用新名字盲目重试；未完成的注册会阻止该租户服务，重开 Store 后完成已记录的创建或回收未发布 staging。启动时也核对旧版本的未注册 UUID 目录：仅在取得目录锁、确认 Manifest 无检查点/SST 且 WAL 只有文件头时回收；有业务记录或无法确认的目录保留供检查，活跃引擎持有的目录不会删除。

同一个根目录只能有一个 Store 管理者，同一个租户目录只能有一个写引擎。句柄、读快照、查询或构建仍活跃时，关闭、删除、恢复返回 BUSY。调用方停止新流量并释放句柄/游标后重试。空闲实例自动释放缓存、句柄和内存，未刷盘内容仍由已同步 WAL 恢复。

v0.8.1 在恢复及失败输出清理时，一次建立 Manifest 文件名集合，避免对每个文件重复遍历全部引用。临时集合计入租户与全局内存预算；预算不足则采用原有逐项检查，不因这项可选优化阻断恢复。`cargo run --release --example recovery_perf -- ROOT seed 1000` 生成多 SST 测试库，随后用 `ROOT open 1000` 测量引擎重开并逐条核对数据；该例不清空操作系统页缓存，不能将结果当作设备冷缓存性能。

控制注册表保留已删除 UUID，不复用身份。16384 租户上限只计未删除注册，不计历史墓碑；墓碑仍增加注册表重写成本，16 MiB 元数据格式上限仍适用。租户名字可以重用但获得新 UUID。损坏租户打开失败缓存到该租户状态；修复文件后先关闭失败实例再重试打开，不应通过删除损坏文件强行启动空库。

## 备份、恢复与迁移

OpenDAL 远端备份由 `--backup-config` 启用；配置、任务轮询、S3 保留清理和新机器导入见 [backup.md](backup.md)。原有 `/backup` 和 `/restore` 保留为本地同步操作，以下先描述它们共享的检查点与恢复协议。远端任务暂存另有 `max_staging_bytes` 预算；未发布的上传和终态任务需要按该文档维护。

备份先建立一致 checkpoint，固定文件集合及已打开的文件描述符，在维护锁外复制并 fsync 后进行完整性校验。后续写入不属于该备份点，合并删除源文件名不会使已固定描述符失效。返回的本地备份 UUID 位于 `backups/<tenant>/<backup>`。本地备份每租户最多 64 份，总占用受 max_local_backup_bytes 与租户磁盘配额的较小值限制；通过 DELETE /v1/tenants/{tenant}/backup/{backup} 回收旧副本，需本租户 admin。创建检查点先在刷盘前检查待刷内存表与元数据空间，再检查预计副本输出加物理空闲余量，复制期间每 256 KiB 再检查余量；共享卷仍应配置容量隔离。多个本地创建/删除/恢复串行，防止检查后并发超额。

恢复仅接受同租户、同持久数据库身份的备份。先复制到 staging 并检查，在该租户无活跃操作时持久记录恢复 journal，再将旧目录移到 trash、staging 切换为当前目录。Active 注册状态同步后，在注册表和复制屏障锁外清理旧目录。锁内只固定当时已存在、无 journal 引用的回收路径，避免误删其他并发恢复的新目录。中途重启按 journal 完成切换。恢复发布状态不确定时，该租户返回 UNAVAILABLE，必须重开 Store 后恢复；不能通过关闭单租户清除这一隔离状态。复制和校验期间该租户仍可读写；普通本地恢复最终发布需释放句柄和快照，否则返回 BUSY 并丢弃本次暂存。复制重建则保留下载副本并后台重试安装，详见复制文档。复制按 256 KiB 作业进入共享 I/O 队列。其他租户可继续操作。运行中的生命周期清理不会删除其他租户尚未发布的 staging；启动时才清理这些遗留目录。

删除租户先持久发布 Deleting、rename 到 trash 并发布 Deleted，递归清理移到注册表及复制屏障锁外执行。恢复的复制、校验同样不持有复制屏障；最终发布重新验证角色和源 epoch。

重启索引重建使用独立的单线程有界工作者，避免耗尽刷盘/合并维护池；按目录提交序号跳过未变化 catalog，停止时在分批处理边界退出并保留可恢复的 BUILDING 状态。已经开始的构建遇到 L0/内存表积压时，在执行下一事务闭包前等待维护推进，等待期间不占写锁或复制屏障，并继续检查快照期限和停止。在线 create_index 的每次事务准入等待最多 5 秒，超时返回 DEADLINE_EXCEEDED；重启恢复构建不设这个单次上限，仍受构建快照期限及停止检查约束。此上限只限制背压等待，不是整次索引扫描或不可中断系统 I/O 的完成期限。普通写入在 L0 或内存表积压时仍返回 RESOURCE_EXHAUSTED，不等待索引构建；客户端应以原操作 ID/重试上下文做有界退避，不能把可重试背压当作永久失败。已执行的事务闭包不会自动重放；内存/磁盘配额、唯一冲突等其他失败仍按错误处理。维护协调器跳过正在打开/恢复的租户 slot。128 项有界维护队列满时从未入队的位置续扫，避免稳定的租户顺序使后排租户长期得不到维护；正在运行的单次任务仍不可抢占。

删除租户只删除在线数据库，备份仍保留；永久删除业务数据时，运维人员还需删除该租户备份并按底层设备的保留策略处理快照。应用没有实现设备级安全擦除。

v0.5.2 在发布删除 journal 前先关闭内存中的写入入口。发布或后续清理失败时，不能将错误响应视为“没有删除”：该租户保持 `UNAVAILABLE`，关闭单租户不会清除此状态。重新打开 Store 后按持久 journal 确认存活或完成删除；其他健康租户仍可操作。不要在原 Store 中通过重试业务写入来判断删除结果。

主键 Get/MultiGet 额外缓存最近访问集合的 UUID，只保留一个条目，按名称长度加 128 字节向租户和全局预算计费。预算不足时跳过缓存准入，不使原本可执行的读取因这个可选缓存失败。缓存绑定目录提交序号和租户实例，旧快照、删除重建及恢复不会复用错误集合身份。

单机迁移可使用停流量、检查点备份复制、目标校验和服务切换。v0.5 另提供 [一主一从在线复制和计划切换](replication.md)，通过 `--replication-config` 启用；这是异步复制，没有多数派共识或自动选主。复制整个存储根应先停止服务，以同时保存控制注册表；不能将活跃目录的普通文件复制当作一致备份。

启用复制后普通 restore/import 被拒绝，需在新的 Store 恢复并重新初始化复制关系。备份继续可用，但 S3 创建/清理只配置一个执行者，切换不会自动迁移备份执行权。默认每租户保留 256 MiB 已刷盘 WAL，计入租户磁盘预算；落后超过日志窗口时会传输完整检查点。`replication-work/` 的业务暂存也需预留磁盘空间。

复制角色保存在 `control/replication.json`，启动配置的 `role` 仅首次有效。计划切换中断后旧主可能保持 fenced；观察双方状态后重试原切换，不能删除状态文件或改配置放开旧主。故障升主必须先在外部隔离旧主，接受异步数据损失；旧主回归须从新空目录重建。启用复制的根注册表为 v2，v0.4 Store 会拒绝打开。

## 故障与指标

新建根注册表为 v5，保留历史状态及已删 UUID 不可复用语义。健康 v4 根在单纯启动、读取时不升级文件；下一次必要的注册表发布才原子迁移，满盘时仍可启动已有数据的读取服务。待完成的生命周期日志以及 v1–v3 兼容迁移仍需要可写空间。升级需同时更新服务与离线恢复程序，旧程序不能打开迁移后的根；升级前保留停机备份。能力接口的 storage_registry=5 表示程序写出的格式，不能据此判断根目录文件已经迁移。WAL/SST 和复制协议未改变。16 MiB 注册表格式上限仍在，达到上限前应结合 `tkv_registry_metadata_bytes`、`tkv_registry_metadata_capacity_bytes` 和 `tkv_registry_deleted_tenants` 预警；容量不足在生命周期状态发布前拒绝，不将未发布的创建留在注册表中。

在线缩配额的 used 检查和限额发布与并发预留同步；预留之间仍可并发，释放不等待配额更新。已有预留不能被强制撤销，当前使用量超过目标配额时仍拒绝缩容。管理排空失败后，索引恢复缓存会失效，入口恢复后可在同一个引擎继续重建，不依赖另一次目录修改或重开。

主节点丢失后的隔离、故障升主、旧节点重建及新 Store 备份恢复，见[故障恢复演练与操作流程](recovery-drill.md)。其中分别记录异步升主与检查点恢复的数据损失、实际读写恢复耗时和完整数据校验，包含可重复运行的 Linux 脚本。

持续写入、合并、复制、备份与 GC 的并行运行，以及独立磁盘写满、WAL 写入/同步 EIO 和重启恢复的验证方法与边界，见[v0.10.1 生产资格验证](production-qualification.md)。其中区分预先拒绝的资源背压与不能盲目重试的未知提交结果。

后台并行引起的轻租户写尾延迟定位、备份进度同步优化及相同负载前后比较，见[尾延迟优化记录](tail-latency-optimization.md)。备份实时进度通过服务 API 查看，阶段和终态持久化；逐文件计数不会单独触发文件/目录同步。

COMMIT_UNKNOWN 后不能继续写入该引擎。新请求不再复用它，旧引用释放后自动关闭；后续打开先校验全部 WAL。健康关闭会在 WAL 同步成功后持久保存 WAL-SYNC 水位，按租户、generation、WAL UUID 和长度匹配；已匹配且未变化的 WAL 不再重写或再次同步，水位也不重复发布。水位缺失、损坏或长度改变时，仍以普通写入重建新 inode、同步文件、原子替换并同步目录，之后才能发布恢复位置，不能只重试旧 inode 的 fsync。未知结果可能在恢复后可见，仍须核对原操作 ID 和条件版本。

重建临时需要最多约一个未刷盘 WAL 文件大小的额外空间。仅 ENOSPC/可用空间不足会降为只读实例，保留已校验数据的读取；context.writable 为 false，租户状态 stats.recovery_read_only 为 true。写入、后台修改、日志导出、复制位置确认和计划切换返回 RESOURCE_EXHAUSTED；只读回放位置不能当作升主依据。该实例继续复用，不每秒重复复制。释放空间后，释放句柄并 close，再打开以完成恢复并重新允许写入。注册表无变化的 Store 启动不再重写 control/tenants.json；新建、格式迁移或待完成的生命周期发布仍需要可写空间。其他打开 IO_ERROR 缓存 1 秒，之后自动重试，close 可提前清除。

WAL 完整帧 CRC 错误、SST 校验失败或活跃文件缺失仍需要有效备份恢复，不能当作未命中或降级忽略。只有健康关闭的引擎可缓存复制位置。已刷盘保留 WAL 被外部删除时，flush 移除历史引用、使旧导出租约失效并继续维护；落后副本通过 LOG_GONE 重建。

installing 在检查点安装、管理操作排空及配额离线预检期间为 true。状态接口包含 commit_seq、memory_bytes、disk_bytes、各层文件数、活动快照数、维护错误，以及进程内累计的 document_bytes、wal_bytes、flush_bytes、compaction_read_bytes、compaction_write_bytes、commits、WAL fsyncs、write_lock_wait_ns，以及 scheduler.completed_jobs、cancelled_jobs、queue_wait_ns、queued_jobs。调度计数在 Store 生命周期内按租户累计；其余引擎指标在重开后清零。读取统计的 blocks_read 表示引擎文件读取，不保证绕过操作系统页缓存；decompressed_bytes 是解压后的字节数。写放大可用 `(wal_bytes + flush_bytes + compaction_write_bytes) / document_bytes` 估算，必须注明区间、索引数和合并是否追平。

打开的租户状态另有 `dsl_cache`，包含 hits、misses、entries、reserved_bytes。最后两项只计当前缓存内条目；调用方继续持有的淘汰条目仍反映在租户总体 memory_bytes 中。Rust 可通过 `TenantHandle::dsl_cache_stats()` 获取同一统计。

持续监测 P95/P99、配额拒绝、L0/各层积压、旧快照、RSS、磁盘余量和维护错误。单次短基准、进程中止恢复及 Linux VM 验证不能替代真实掉电、fsync 故障、设备损坏和长时间生产压测。

v0.5.1 从库的 commits、wal_bytes、document_bytes 包括实际回放的原始事务。一次整页回放可对应多个 commits 和一次 WAL fsync/I/O 追加，不能用 I/O 任务数直接推断事务数。追赶积压时不再每页固定等待轮询间隔，因此短时复制 I/O 会更密集；仍受逐租户轮次、内存预算、L0 背压和共享 I/O 队列限制。具体对比与边界见 [v0.5.1-validation.md](v0.5.1-validation.md)。

## 时态数据运维

v0.6 的知识历史和操作收据保存在租户受管集合中，自动进入现有本地及 OpenDAL 检查点备份。v0.8 可设置租户统一 retention_seconds，回收旧知识与收据；当前业务状态不失效，仍不能通过普通 CRUD 手动删除历史头。回收状态和升级规则见 [retention.md](retention.md)。恢复到旧检查点后，丢失的知识 UUID 返回 `KNOWLEDGE_UNAVAILABLE`，不会复用相同 ordinal 冒充旧历史。

初始化时可以下调每标识片段数和设置时钟偏移容忍度，配置之后不可变。`CLOCK_SKEW` 表示进程内时钟跳变或持久时间回退超过容忍度，应修复时间同步；不能通过篡改时间线绕开。完整资源、版本升级和证据可信边界见 [identity.md](identity.md)。

## v0.7 集成配置

每个 token 必须配置稳定 subject；轮换哈希时保持主体不变。配置在启动时加载。`/health` 用于存活，`/ready` 和 `/ready/write` 用于读/写就绪；SIGTERM 与 SIGINT 先将就绪置为 503，保持监听 2 秒供健康检查观察，然后停止接收连接并给予既有 HTTP 请求 30 秒排空；超时以非零状态终止进程。正常排空后停止复制传输并关闭 exporter。系统调用永久挂起、后台组件或 exporter 关闭耗时不属于 HTTP 排空期限，部署仍需进程管理器设置最终终止期限。不要将 SIGKILL 当作优雅退出。

可独立启停 Prometheus 指标、OTLP 链路和日志，配置与资源边界见 [可观测性](telemetry.md)。v0.7 双节点升级与不可回退的注册表边界见 [中间件集成](middleware.md)。

HTTP 在执行池已满时先拒绝请求，避免读取注定无法准入的正文；这只是非阻塞预检，准入和正文完成后仍须实际取得执行名额，竞争下可能返回 429。空正文不占正文接收池，冷预算锁等待由独立准入池限制。取消或五秒超时后，仍在阻塞任务中的准入与租户名额保持到任务退出，执行名额从未交给该等待。JSON 解码复用已取得的预算，不再次为预算取得 slot 锁。

普通执行、建索引、维护、生命周期操作使用各自有界执行池。单租户同时最多一个重任务（建索引或维护），另有一个独立生命周期名额。关闭、删除、改配额和检查点安装触发排空后，索引构建在扫描、增量处理或写入等待的检查点返回 BUSY，释放构建自身的快照与 HTTP 请求句柄；已登记的 BUILDING 保留，租户重新打开后可自动重建。无需先删除索引才能尝试这些管理操作。已有系统 I/O、锁等待或嵌入式调用方长期保留的句柄仍可能使一秒排空超时；此时恢复入口，不强制析构外部引用或作废普通读快照。

本地及远端备份在检查点复制完成后释放在线租户句柄，私有副本的校验、哈希及上传不再延长在线排空。复制期间和其他活动引用仍受原排空期限约束；备份的在用内存继续计入租户预算，增加配额可独立发布，缩容仍可能因预算不足被拒。备份保存捕获时的租户元信息，后续在线配额变化不会改写这份检查点清单。

备份任务控制文件的 I/O 错误可能发生在重命名之后，不能根据请求报错就再次新建同租户任务。当前进程保留未知任务身份，可从 backup-jobs 查询 interrupted，并按原 ID retry（仅 create/verify/prune）或检查后 forget；其他租户的状态查询和业务执行不等待这份任务的文件同步。结束状态发布失败同样保留所有权，避免两个未结束的持久任务让下次启动失败。细节见[备份元信息边界验证](special-stability4-20261107.md)。

HTTP 先用 try_lock/try_read 非阻塞取得已缓存预算。全局 registry/slots 目录锁竞争时，在异步任务中每隔一毫秒重试，不占冷准入名额或阻塞线程；等待仍受原预算准备/正文期限约束，最多五秒，读取控制指定更短期限时随之缩短。仅租户 slot 锁忙或尚无 slot 时，回退到受独立准入名额约束的阻塞任务；真正的冷准入池满仍可返回 429。热请求不经过准入池的排队锁，正文增长只使用原子计数器。慢正文继续不占执行名额。

内置 HTTP/1 服务使用已有 Hyper/Tokio 定时器限制请求头及空闲 keep-alive 等待；持续慢速发送头部字节不会刷新完整头部的期限。达到连接上限后继续 accept 并立即关闭溢出连接，客户端可能看到 EOF 或 reset。写空闲期限仅限制 socket 写入无进展，不计入处理器等待，长索引或检查点准备不会被当作读空闲而断开。嵌入式服务可使用 `http::Listener::serve(router, shutdown)` 获得同一政策；直接把 Listener 传给 axum::serve 只有限连和写超时，宿主需自行配置请求头定时器。

默认 keep-alive 等待与请求头期限均为 5 秒。客户端连接池应在更短的空闲时间回收连接；内置 Rust Client 和复制客户端默认 4 秒。服务端调低此配置时，调用方需相应缩短连接池空闲时间。任何关闭竞态都不保证请求已执行与否，非幂等请求不可盲目重试，沿用操作 ID/条件版本契约。当前锁定依赖未启用 HTTP/2，内置监听器为 HTTP/1；不能仅凭 axum 的 auto builder 名称推断旧二进制支持 h2c。
