# 运维与资源预算

## 配置

`Options` 可通过 Rust 构造或 HTTP 服务 `--config` JSON 文件设置。未知配置字段拒绝。以下为默认值：

| 字段 | 默认值 |
|---|---:|
| global_memory_bytes | 4 GiB |
| tenant_memory_bytes | 512 MiB |
| tenant_disk_bytes | 100 GiB |
| cache_bytes | 128 MiB |
| memtable_bytes | 16 MiB |
| block_bytes | 16 KiB |
| target_sst_bytes | 16 MiB |
| level_base_bytes | 64 MiB，后续层每层扩大 10 倍 |
| io_workers | 4 |
| max_tenant_requests | 32 |
| idle_seconds | 300 |
| snapshot_seconds | 60 |
| index_build_seconds | 3600，构建快照单独上限 |
| max_snapshots | 256 |
| max_document_bytes | 1 MiB |
| max_batch_operations | 1000 |
| max_batch_bytes | 16 MiB |
| max_read_keys | 1000 |
| max_page_size | 1000 |
| max_scan | 100000 |
| query_ms | 5000 |
| max_response_bytes | 16 MiB |
| max_query_bytes | 64 MiB |
| l0_trigger / l0_stop | 4 / 12 |

文档格式上限 16 MiB、输入批次格式上限 64 MiB、响应上限可配置为 1–64 MiB、展开后的 WAL 原子记录上限 64 MiB；这些是实现边界，调高配额不会绕过。批次可能因覆盖索引扩张而超过 WAL 上限并被整体拒绝。批次数量、读键数和分页大小可调至最多 100000，但仍受字节、扫描、时间及内存预算约束。JSON 深度最多 32、字段/元素数最多 16384、编码键最多 8 KiB。

缓存容量不能直接等同进程 RSS：引擎计入 memtable、块缓存及被引用块、版本目录、事务变更、查询候选和游标的预算；Rust 分配器、网络栈和调用方保留的返回值仍占进程内存。HTTP 请求正文及发送中的响应另计全局预算；JSON 树在解析前按结构估算并同时计入目标租户预算。冷租户恢复、解析与引擎操作在有界阻塞工作池执行。备份校验和恢复暂存实例与在线实例共用该租户内存计数器。部署时应为这些开销预留余量，并以 RSS/cgroup 和引擎预算双重观测。

租户缓存上限取配置值与租户配额三分之一的较小者。维护与数据块读取使用有界共享工作池；I/O 按租户轮询分配任务，单批独立块最多 8 个在途。此调度提供任务级公平，不构成磁盘 IOPS 或带宽的硬 SLA。正常达到 memtable 阈值由后台刷盘；积压到阈值 3 倍时前台尝试刷盘，维护锁忙时立即交还后台，超过 4 倍时拒绝继续增长，避免排在整次合并之后。刷盘优先于同租户合并；各层积压按压力选取合并，持续积压对该租户写入返回背压。

读 I/O 队列最多排队 4096 项；写入和持久化任务不受读队列水位拒绝，仍由调用侧并发和租户预算约束。未进入队列的 WAL 追加失败不标记 COMMIT_UNKNOWN；已经开始追加或同步失败仍隔离写入。内存不足时按需逐帧淘汰块缓存，保留其余可用帧。组提交在同步期间释放写锁，只发布同步开始前捕获的序号；后续暂存需要下一次同步。刷盘/合并的最终 Manifest 发布由维护锁串行化，文件同步放在写锁外；WAL 轮转的短发布阶段仍保持写入互斥。

v0.3 的 DSL AST 缓存另外计入同一租户/全局内存预算，最多 256 项、4 MiB 保守计费容量；查询目录缓存最多 128 个集合、4 MiB。它们不是预算外的内存，也不是进程 RSS 的硬上限。外部 Arc 持有已淘汰准备语句或执行中的目录引用时，预留量保持到最后引用释放，故总持有量可能高于缓存内条目容量，但不能绕过全局/租户预算。纯 `Prepared::parse` 的分配由嵌入式调用方承担；推荐 `TenantHandle::prepare_dsl` 取得计费准备语句。

DSL 语句最多 64 KiB，参数编码量受 `max_batch_bytes` 限制，展开后的绑定临时内存受 `max_query_bytes` 限制。参数多次引用会累计计费，在克隆前拒绝超额展开。AST 缓存随租户实例关闭/恢复而释放，目录缓存随 DDL 序号失效；普通写入不使语法缓存失效。

磁盘预算包含当前租户目录中的 WAL、SST、构建增量、旧版本及临时输出。普通写入只使用配额的 80%，为维护预留空间；刷盘/合并先保守预留输出空间，再按实际目录占用校准。v0.8.1 允许复制回放使用维护预留空间，防止到达前台写入门槛后无法回放删除记录；总配额仍生效。因保守预留可能提前拒绝写入。备份目录单独管理，不包含在在线数据库配额内，需配置外部卷容量或运维保留策略。

v0.10.1 校准磁盘用量时持有维护锁固定文件发布和 WAL 轮转，但不在遍历目录期间持有写锁；最后用短写锁读取当前 WAL 实际长度并发布总量，包含扫描期间完成的提交。旧快照释放导致的过期 SST 删除可以使统计暂时偏大，下次校准收敛。维护频率、配额门槛及持久化顺序保持不变。

## 生命周期

同一个根目录只能有一个 Store 管理者，同一个租户目录只能有一个写引擎。句柄、读快照、查询或构建仍活跃时，关闭、删除、恢复返回 BUSY。调用方停止新流量并释放句柄/游标后重试。空闲实例自动释放缓存、句柄和内存，未刷盘内容仍由已同步 WAL 恢复。

v0.8.1 在恢复及失败输出清理时，一次建立 Manifest 文件名集合，避免对每个文件重复遍历全部引用。临时集合计入租户与全局内存预算；预算不足则采用原有逐项检查，不因这项可选优化阻断恢复。`cargo run --release --example recovery_perf -- ROOT seed 1000` 生成多 SST 测试库，随后用 `ROOT open 1000` 测量引擎重开并逐条核对数据；该例不清空操作系统页缓存，不能将结果当作设备冷缓存性能。

控制注册表保留已删除 UUID，不复用身份。16384 租户上限只计未删除注册，不计历史墓碑；墓碑仍增加注册表重写成本，16 MiB 元数据格式上限仍适用。租户名字可以重用但获得新 UUID。损坏租户打开失败缓存到该租户状态；修复文件后先关闭失败实例再重试打开，不应通过删除损坏文件强行启动空库。

## 备份、恢复与迁移

OpenDAL 远端备份由 `--backup-config` 启用；配置、任务轮询、S3 保留清理和新机器导入见 [backup.md](backup.md)。原有 `/backup` 和 `/restore` 保留为本地同步操作，以下先描述它们共享的检查点与恢复协议。远端任务暂存另有 `max_staging_bytes` 预算；未发布的上传和终态任务需要按该文档维护。

备份先建立一致 checkpoint，固定文件集合及已打开的文件描述符，在维护锁外复制并 fsync 后进行完整性校验。后续写入不属于该备份点，合并删除源文件名不会使已固定描述符失效。返回的本地备份 UUID 位于 `backups/<tenant>/<backup>`。

恢复仅接受同租户、同持久数据库身份的备份。先复制到 staging 并检查，在该租户无活跃操作时持久记录恢复 journal，再将旧目录移到 trash、staging 切换为当前目录。Active 注册状态同步后，在注册表和复制屏障锁外清理旧目录。锁内只固定当时已存在、无 journal 引用的回收路径，避免误删其他并发恢复的新目录。中途重启按 journal 完成切换。恢复发布状态不确定时，该租户返回 UNAVAILABLE，必须重开 Store 后恢复；不能通过关闭单租户清除这一隔离状态。复制和校验期间该租户仍可读写；最终发布需释放句柄和快照，否则返回 BUSY 并丢弃本次暂存。复制按 256 KiB 作业进入共享 I/O 队列。其他租户可继续操作。运行中的生命周期清理不会删除其他租户尚未发布的 staging；启动时才清理这些遗留目录。

删除租户先持久发布 Deleting、rename 到 trash 并发布 Deleted，递归清理移到注册表及复制屏障锁外执行。恢复的复制、校验同样不持有复制屏障；最终发布重新验证角色和源 epoch。

重启索引重建使用独立的单线程有界工作者，避免耗尽刷盘/合并维护池；按目录提交序号跳过未变化 catalog，停止时在分批处理边界退出并保留可恢复的 BUILDING 状态。已经开始的构建遇到 L0/内存表积压时，在执行下一事务闭包前等待维护推进，不占写锁或复制屏障，并继续检查快照期限和停止；内存/磁盘配额、唯一冲突等其他失败仍按错误处理。维护协调器跳过正在打开/恢复的租户 slot。

删除租户只删除在线数据库，备份仍保留；永久删除业务数据时，运维人员还需删除该租户备份并按底层设备的保留策略处理快照。应用没有实现设备级安全擦除。

v0.5.2 在发布删除 journal 前先关闭内存中的写入入口。发布或后续清理失败时，不能将错误响应视为“没有删除”：该租户保持 `UNAVAILABLE`，关闭单租户不会清除此状态。重新打开 Store 后按持久 journal 确认存活或完成删除；其他健康租户仍可操作。不要在原 Store 中通过重试业务写入来判断删除结果。

主键 Get/MultiGet 额外缓存最近访问集合的 UUID，只保留一个条目，按名称长度加 128 字节向租户和全局预算计费。预算不足时跳过缓存准入，不使原本可执行的读取因这个可选缓存失败。缓存绑定目录提交序号和租户实例，旧快照、删除重建及恢复不会复用错误集合身份。

单机迁移可使用停流量、检查点备份复制、目标校验和服务切换。v0.5 另提供 [一主一从在线复制和计划切换](replication.md)，通过 `--replication-config` 启用；这是异步复制，没有多数派共识或自动选主。复制整个存储根应先停止服务，以同时保存控制注册表；不能将活跃目录的普通文件复制当作一致备份。

启用复制后普通 restore/import 被拒绝，需在新的 Store 恢复并重新初始化复制关系。备份继续可用，但 S3 创建/清理只配置一个执行者，切换不会自动迁移备份执行权。默认每租户保留 256 MiB 已刷盘 WAL，计入租户磁盘预算；落后超过日志窗口时会传输完整检查点。`replication-work/` 的业务暂存也需预留磁盘空间。

复制角色保存在 `control/replication.json`，启动配置的 `role` 仅首次有效。计划切换中断后旧主可能保持 fenced；观察双方状态后重试原切换，不能删除状态文件或改配置放开旧主。故障升主必须先在外部隔离旧主，接受异步数据损失；旧主回归须从新空目录重建。启用复制的根注册表为 v2，v0.4 Store 会拒绝打开。

## 故障与指标

主节点丢失后的隔离、故障升主、旧节点重建及新 Store 备份恢复，见[故障恢复演练与操作流程](recovery-drill.md)。其中分别记录异步升主与检查点恢复的数据损失、实际读写恢复耗时和完整数据校验，包含可重复运行的 Linux 脚本。

持续写入、合并、复制、备份与 GC 的并行运行，以及独立磁盘写满、WAL 写入/同步 EIO 和重启恢复的验证方法与边界，见[v0.10.1 生产资格验证](production-qualification.md)。其中区分预先拒绝的资源背压与不能盲目重试的未知提交结果。

后台并行引起的轻租户写尾延迟定位、备份进度同步优化及相同负载前后比较，见[尾延迟优化记录](tail-latency-optimization.md)。备份实时进度通过服务 API 查看，阶段和终态持久化；逐文件计数不会单独触发文件/目录同步。

COMMIT_UNKNOWN 后不能继续写入该引擎。停止该租户访问、释放句柄、关闭后重新打开，回放 WAL，并核对条件版本。WAL 完整记录 CRC 错误、SST 校验失败或文件缺失需要从有效备份恢复，不能当作未命中。

状态接口包含 commit_seq、memory_bytes、disk_bytes、各层文件数、活动快照数、维护错误，以及进程内累计的 document_bytes、wal_bytes、flush_bytes、compaction_read_bytes、compaction_write_bytes、commits、WAL fsyncs、write_lock_wait_ns，以及 scheduler.completed_jobs、cancelled_jobs、queue_wait_ns、queued_jobs。调度计数在 Store 生命周期内按租户累计；其余引擎指标在重开后清零。读取统计的 blocks_read 表示引擎文件读取，不保证绕过操作系统页缓存；decompressed_bytes 是解压后的字节数。写放大可用 `(wal_bytes + flush_bytes + compaction_write_bytes) / document_bytes` 估算，必须注明区间、索引数和合并是否追平。

打开的租户状态另有 `dsl_cache`，包含 hits、misses、entries、reserved_bytes。最后两项只计当前缓存内条目；调用方继续持有的淘汰条目仍反映在租户总体 memory_bytes 中。Rust 可通过 `TenantHandle::dsl_cache_stats()` 获取同一统计。

持续监测 P95/P99、配额拒绝、L0/各层积压、旧快照、RSS、磁盘余量和维护错误。单次短基准、进程中止恢复及 Linux VM 验证不能替代真实掉电、fsync 故障、设备损坏和长时间生产压测。

v0.5.1 从库的 commits、wal_bytes、document_bytes 包括实际回放的原始事务。一次整页回放可对应多个 commits 和一次 WAL fsync/I/O 追加，不能用 I/O 任务数直接推断事务数。追赶积压时不再每页固定等待轮询间隔，因此短时复制 I/O 会更密集；仍受逐租户轮次、内存预算、L0 背压和共享 I/O 队列限制。具体对比与边界见 [v0.5.1-validation.md](v0.5.1-validation.md)。

## 时态数据运维

v0.6 的知识历史和操作收据保存在租户受管集合中，自动进入现有本地及 OpenDAL 检查点备份。v0.8 可设置租户统一 retention_seconds，回收旧知识与收据；当前业务状态不失效，仍不能通过普通 CRUD 手动删除历史头。回收状态和升级规则见 [retention.md](retention.md)。恢复到旧检查点后，丢失的知识 UUID 返回 `KNOWLEDGE_UNAVAILABLE`，不会复用相同 ordinal 冒充旧历史。

初始化时可以下调每标识片段数和设置时钟偏移容忍度，配置之后不可变。`CLOCK_SKEW` 表示进程内时钟跳变或持久时间回退超过容忍度，应修复时间同步；不能通过篡改时间线绕开。完整资源、版本升级和证据可信边界见 [identity.md](identity.md)。

## v0.7 集成配置

每个 token 必须配置稳定 subject；轮换哈希时保持主体不变。配置在启动时加载。`/health` 用于存活，`/ready` 和 `/ready/write` 用于读/写就绪；SIGTERM 与 SIGINT 先将就绪置为 503，保持监听 2 秒供健康检查观察，然后停止接收连接并给予既有 HTTP 请求 30 秒排空；超时以非零状态终止进程。正常排空后停止复制传输并关闭 exporter。系统调用永久挂起、后台组件或 exporter 关闭耗时不属于 HTTP 排空期限，部署仍需进程管理器设置最终终止期限。不要将 SIGKILL 当作优雅退出。

可独立启停 Prometheus 指标、OTLP 链路和日志，配置与资源边界见 [可观测性](telemetry.md)。v0.7 双节点升级与不可回退的注册表边界见 [中间件集成](middleware.md)。
