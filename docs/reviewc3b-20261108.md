## 其他处理与取舍

- `--archive evidence` 正确相对当前目录解析，原修复/崩溃回归使用此写法；原 WAL 长度只读取一次用于报告。
- prune 因未来时间停止时新增服务累计指标 `tkv_backup_prune_clock_unsafe_total` 和包含 tenant/job 的日志。实际任务返回 BACKUP_CLOCK_UNSAFE，认证 `/metrics` 显示计数增长，随后 verify/restore 仍可成功。告警示例见 [telemetry.md](telemetry.md)。
- 普通同步整轮上限为 **150 秒**，单个日志请求上限仍为 **120 秒**，以免状态查询消耗少量时间后任何请求都拿不到完整单页额度。剩余不足 **100 ms** 不发日志请求；升主的整个异步等待仍最多 **120 秒**，不会因不足完整额度而误触发快照。具体契约见 [replication.md](replication.md#请求与凭证边界2026-11-08)。
- epoch 先保存、租户后发布的安全顺序保持不变，二者不是一个原子事务。持久 phase 是操作意图和进展记录，崩溃时可落后实际状态，必须结合节点与生命周期状态判断。没有自动回滚 epoch，也不自动把旧从库重新接上。
- 本次不再向源码提交加入整批原始日志，仅提交这份简要报告。完整命令输出和源码校验值另存本地验证包；不改写上一提交的历史证据，也不创建额外 GitHub Release。
