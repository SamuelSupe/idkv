# 主体反查和变更历史验证（2026-11-09）

后续批量迁移、历史回收、容量边界及 Rust 1.99.1 的增量验证见[迁移优化验证记录](subject-maintenance-validation-20261109.md)。下文保留本阶段的原始环境和测量。

实现位于当前 b006c00 工作树，接续此前 resolve_many 改动。入口为 `/identity/ids`、`/identity/history`，对应 DSL `ids`、`history` 和 Rust/HTTP Client 的 `get_subject_identifiers`、`get_subject_history`。参数和升级规则见 [identity.md](identity.md#主体反查和变更历史)。

## 实现与边界

- 主体反向关系按主体、标识摘要及知识 ordinal 存储。关系增减与时间线、知识头、收据一起原子提交；读取前驱关系后，用同一快照中的时间线匹配业务时间。
- 变更事件记录来源、操作者、记录时间、业务有效区间及实际属性/绑定差异；一条共享事件通过指针关联所有受影响主体。替换标识为一条含两个标识变化的事件，无效操作不生成变更事件，幂等重试不重复记账。
- 分页共用已有游标注册表、快照与主体配额，绑定过滤器、读者、租户、节点代际和复制历史；保留期、失败不消费游标、物理墓碑推进、扫描/内存/响应预算均经过验证。
- 旧数据只重建可证明的反向关系，分批持久化进度，兼容期间的新写入和重启。升级前缺失的事件不会合成，coverage 明示 legacy_history_missing 和保留策略。
- 事件及指针分开过期；反向版本保留最低有效知识的前驱基线，包括 absent 基线。已启用和后启用保留策略均有清理路径。
- 根注册表升为 6，复制协议升为 4，启动先持久升级根以排除旧写入器；原有 v5 紧凑删除历史编码保留。主从及离线工具应一起升级，不能直接降级。

## 运行验证

环境：OrbStack Ubuntu 25.10 ARM64，Rust/Cargo 1.90.0；macOS 共享工作目录。运行测试和示例均在 Linux，格式整理为静态检查。

```sh
CARGO_TARGET_DIR=/var/tmp/idkv-p01-target-20261108 \
TMPDIR=/var/tmp/idkv-p01-tmp-20261108 \
cargo test --all-features --no-fail-fast -- --test-threads=4
cargo clippy --all-targets --all-features -- -D warnings
cargo fmt --all -- --check
git diff --check
```

全量回归：**288 项通过，0 失败**。覆盖的实际行为包括：

- 多个知识版本与业务时间边界，逐项比较反查和正向 resolve；全量转移、部分区间转移、替换、解绑和空关系。
- 原主体/新主体读取同一个重绑定 event_id；属性差异区分缺失和 null，保留嵌套值、UTF-8 及 u64 精度；重复操作与无效果操作不新增事件。
- 续页期间新提交不混入旧快照，历史知识续页不能绕过逻辑到期；跨主体/过滤器游标被拒且不消费原 token。分页越过 90 条物理墓碑，预算失败后可续页且内存恢复；超过响应上限的大历史页不泄漏快照，改用小页可完整读回。
- 小批次上限下，展开记录超限不发布任何正文、反向关系、事件、知识或收据；真实进程崩溃注入后核对回执、正向结果、反查及事件同时存在或同时不存在。
- 旧索引缺失时拒绝反查，分批恢复在重启后继续；重建中排序落在游标之前的新修正仍正确可查，历史版本归属保持一致；query_ms=1、max_query_bytes=1 的客户端限制下，后台重建仍可完成。
- 后启用 retention 后，事件正文与指针实际回收，反查保留正/负前驱基线。原注册表容量拒绝仍保持磁盘注册表不变。
- HTTP 原生与 DSL 在只读权限下结果一致，跨租户访问被拒。真实双节点复制、HTTP SDK 页续传及计划切换验证通过；SDK 返回绑定原节点的包装游标。

探索阶段与编译并行运行时，一项既有建索引排空测试曾未在其期限内到达 READY；未修改该实现，独立的 126 项库级回归及最终固定并发度全量回归均通过。精确内存计量测试已隔离后台任务并预热正常缓存，继续逐次断言读请求的临时内存和快照释放。

另实际运行 `examples/identity.rs` 核对原生与 DSL 的反查结果。`examples/identity_subjects.rs` 是可重复执行的批量、分页及并发写入验证程序，目录必须是新目录，不覆盖已有数据库。

## 小样本性能

命令：

```sh
cargo run --locked --release --example identity_subjects -- /var/tmp/idkv-subjects-new
```

默认 Options，预先 flush/compact，并预热一次。每轮读完该主体的全部标识，页大小 100；单独读取 20 轮，再与属性写入线程同时读取 20 轮。写入线程至少执行 100 次，并持续到读取结束；每次写入含事件、指针和幂等回执。最后检查当前已确认属性以及每次已确认更新对应的唯一历史事件。

|---:|---:|---:|---:|---:|---:|
| 64 | 1.681 / 1.853 ms | 1.945 / 3.358 ms | 3.689 / 15.153 ms | 100 | 128 |
| 1000 | 37.002 / 44.333 ms | 40.592 / 55.888 ms | 3.292 / 6.824 ms | 219 | 2000 |

历史全量读取分别为 165 条 / 0.930 ms、1220 条 / 10.041 ms；事件数量等于创建事件 + 各标识绑定事件 + 已确认属性更新，所有更新均核对且无重复。性能数据是本机预热缓存、单主体的微基准，20 个读取样本的 p99 接近最大值，不代表冷盘、网络 RTT、生产 SLO 或长期稳定性结论。

未执行大规模多租户长时间 soak、真实设备断电或完整旧版本二进制升级演练；旧数据升级通过旧存储形态夹具和重启续建验证。此前 resolve_many 的性能记录是另一个阶段，不作为本功能的前后性能对比。原始 Linux 日志保留在 `/var/tmp/idkv-subject-tests-final5-20261109.log`、`/var/tmp/idkv-subject-bench-final3-20261109.log`，不把批量运行日志加入仓库。
