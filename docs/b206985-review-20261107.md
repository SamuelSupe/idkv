# b206985 性能与稳定性审查修复（2026-11-07）

基线 `b2069851481914710dd82d280f69a8681b12fbe3`。本轮逐项核对审查意见，并在独立的基线源码中运行新增回归作为对照。证据在 [b206985-review-20261107](../bench-results/b206985-review-20261107/)。WAL/SST 格式、复制协议及已确认数据契约保持不变。

## 逐项核实

| 报告项 | 结论与最终处理 |
|---|---|
| 1. 全局本地备份锁 | 属实。锁改为 slot 内的每租户锁；本租户创建、删除与恢复仍串行。回归锁住 A 的备份通道，B 的完整备份仍完成，A 的删除等待到锁释放 |
| 2. 一个租户占满维护池 | 属实。每租户最多一个维护请求，覆盖准入准备与执行，取消后的阻塞工作仍持有名额。回归阻塞 A 的索引事务，另三个建索引请求被立即拒绝，B 的备份完成。四个不同租户仍可能用满全局四个名额；这是有界总额，不承诺任意租户维护请求永不被拒 |
| 3. 连接上限无空闲回收 | 属实。复用已安装的 Hyper/Tokio，为内置 HTTP/1 服务配置请求头完整读取期限；该期限也回收空闲 keep-alive，持续收到零碎头部不重置期限。达到上限后继续 accept 并关闭溢出连接。socket 写期限保留，处理器等待不计为读空闲。单元测试覆盖长处理器、初始空闲、半截请求头、keep-alive、连接溢出及写背压 |
| 4. 查询预算影响 GC/写事务 | 属实。到期队列之外，知识下界、history 和 migration 也改用物理分页，墓碑推进持久游标；分页完成看扫描器是否真正耗尽，不看可见行数。GC 和索引批次使用自身分页/构建规则，不套查询期限。普通事务的单次存储读取仍有限额，但不再把 query_ms 当作整笔原子写入的总期限 |
| 5. durable 分类包含大块后台工作 | 属实。分开 WAL/注册发布、前台读取和后台工作；合并/校验读取、SST 输出、备份及检查点拷贝进入后台层。租户轮询保持，WAL 连续八项后让读取推进，连续八项前台工作后给后台一次机会。只读任务能取消，后台写入仍须完成；不能把调度优先级变成取消已开始的持久输出 |
| 6. 正文已读完才发现执行池满 | 属实。接收前做非阻塞执行余量预检；空正文提前持有执行名额并跳过正文池，非空正文继续不占执行名额。接收完仍需真正取得执行名额，竞争时可能被拒。测试用一旦被读取就失败的正文，证明池已满时不会读取它；原慢正文测试收紧到恰好占满正文池，GET 仍成功 |
| 7. writer 内编码 Manifest | 属实。预检先 clone 再在锁外编码；获取检查点文件描述符后也先释放 writer/maintenance，再编码估算大小。持久 Manifest 发布顺序不变 |
| 8. 日志退避与初始化混用 | 属实。普通日志使用独立退避表；BUSY、RESOURCE_EXHAUSTED、DEADLINE_EXCEEDED 最长一秒，其他错误最长三十秒。成功日志只清日志退避，不清初始化退避。真实 HTTP 回归连续十二次返回 BUSY，随后恢复复制，未重复全量初始化 |
| 9. 管理排空副作用 | 属实。配额、删除、本地恢复的等待不持节点角色许可，发布前重新取得并校验；close 原本就不持此许可。普通管理操作不再主动作废快照/游标，长期引用导致一秒后 BUSY 并恢复入口。副本安装仍按既定策略可撤销旧快照，以免热读阻止安装；不是改变副本协议 |
| 10. 切换遇短锁竞争直接 BUSY | 属实。整个目录共享最多一百毫秒的短竞争重试预算，不是每租户各等一百毫秒；持续竞争仍明确 BUSY。冷恢复仍在节点屏障外；重试不掩盖 COMMIT_UNKNOWN、真实损坏或目录变化 |
| 低优先级：TTL 重复 STATE 读取/解析 | 存在额外开销。保留策略与 GC 状态在事务内缓存，写/删对应键立即失效，缓存不跨事务；按租户/全局预算计费，解码值的引用继续携带计费，求值结束释放无用缓存后再预留提交内存。事务仍可被共享读取，不因缓存丧失 Sync |

## 基线复现与回归

把八项可在原 API 上运行的新行为测试加入独立的 b206985 源码，全部出现预期行为失败：两项墓碑 GC、写入期限、备份跨租户阻塞、管理排空、位置短竞争、维护池占满及满池正文预检。对照未修改生产逻辑；只给 HTTP 测试声明已存在的 Hyper 开发依赖，备份锁测试改为取得旧版本对应的全局锁。每项失败日志及输入测试原文分别见 `control-*.log`、`control-test-input.json` 和 `control-results.json`。

新版本还覆盖缓存同事务失效、后台 I/O 与读取公平、连接期限、复制瞬时退避等行为；已有事务墓碑预算、历史 predecessor 基线、主从切换、崩溃恢复及小配额复制测试继续运行。

墓碑回归将 max_scan 下调到 8，构造 128 个头部墓碑，以较小数据量触发同一预算边界；并验证到期删除和历史 predecessor 基线。日志退避测试通过真实 HTTP 连续制造十二次 BUSY，推进测试中的退避时点以免空等，验证恢复后继续复制且不重新初始化。

## 验证边界

所有后端运行使用 OrbStack Ubuntu Linux aarch64 的原生 `/var/tmp`，与宿主共享的源码目录只用于编辑和保存日志。对照与修复使用不同 Cargo target，关闭增量编译，避免不同源码根的构建产物混用。运行中的二进制另外复制固定，不覆盖其文件。

物理 I/O 不可抢占，优先级不是带宽或尾延迟硬保证。查询预算不再覆盖整笔写入，但单次普通存储读取仍可能因自己的截止时间失败；大原子写入的累计成本由批次数、字节和配额约束，嵌入式闭包中的外部阻塞仍由调用方负责。保留磁盘预算、短读预算和写入背压；没有靠放宽这些边界让验证通过。

连接保护适用于 CLI 和 `http::Listener::serve`。直接将 Listener 传给 axum::serve 不会自动给 Hyper 配置请求头定时器；嵌入式 Router 的宿主仍需提供自己的连接政策。已运行的处理器不受请求头期限截断，停机仍遵循两秒 not-ready 加三十秒请求排空及最终进程终止规则。
