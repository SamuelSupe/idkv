# 复制导出租约阻塞 WAL 恢复：修复与验证

本轮修复 [P0/P1 审查](p01-review-20261108.md) 确认的 P1：检查点导出或追赶租约持有源引擎，WAL 同步失败后，即使 I/O 已恢复，业务仍须等待复制任务释放引擎。基础版本为 `6bd18f3`；全部证据保存在 [p01-fix-20261108](../bench-results/p01-fix-20261108/)。

## 修复行为

`LogRetention` 改为弱引用引擎。健康租约由 manager 显式检查，仍阻止空闲关闭和管理关闭，以保留其 WAL；进入 `recovery_required` 后，租约失效且不能再续期，manager 可以释放并重开旧引擎。旧租约无法附着到新引擎。业务恢复不依赖副本完成下载、手工 release、`Service::start` 的过期轮询或旧目录清理。

准备阶段也释放不必要的所有权：复制完成后先释放在线 TenantHandle，再对独立检查点文件计算 SHA-256。复制每个 256 KiB 块检查源引擎恢复状态，哈希每个 1 MiB 块检查租约有效性。出错时停止准备，由既有失败路径释放生成占位并安排清理。共享检查点复制路径同样适用于本地及远端备份，因此相应文档同步说明了 COMMIT_UNKNOWN 中止与重试行为。持久格式、复制协议和公共函数签名不变。

取消在块边界协作执行，不能中断已经进入的系统 I/O；应用自身长期持有的 Engine/TenantHandle 仍须释放。没有绕过 close 的引用计数、快照或独占锁检查。

## 同负载真实服务对照

在 OrbStack Ubuntu Linux aarch64、原生 Btrfs 上运行独立 HTTP 服务。前后均使用相同脚本、同样的 100 条故障租户文档及 10 条对照租户文档，并注入一次限定根目录内 WAL fsync 的 EIO；收到 COMMIT_UNKNOWN 后立即撤销注入。

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 保持活动导出、继续取分块 | 6.05 秒观察窗内 111 次写入失败；close 为 BUSY | 约 7.03 ms 首次写入成功，旧租约拒绝分块，close 成功 |
| 私有导出 SST 哈希读取暂停 | 6.05 秒观察窗内 114 次写入失败 | 哈希仍暂停时约 4.59 ms 恢复；恢复哈希后旧准备返回 SNAPSHOT_EXPIRED，新导出成功 |
| 正常副本初始化，目标租户分块响应暂停 | 6.05 秒观察窗内 115 次写入失败，计划切换返回 COMMIT_UNKNOWN | 传输仍暂停时约 6.80 ms 恢复；恢复传输后副本完成同步，计划切换成功 |
| 健康租约，idle_seconds=1 | 下载、追赶各闲置 2.2 秒仍保留源引擎；release 后可空闲关闭 | 同样通过，确认弱引用没有破坏健康的长传输保留 |

6 秒是主动设置的观察窗口，不是原版恢复上限。毫秒值是本轮单次样本，不代表 P99 或生产 RTO 保证。修复后的三个 EIO 场景在撤销故障后的业务写入错误数均为 0；故障本身的 COMMIT_UNKNOWN 保留，不会伪装为已确认成功。正常复制场景在暂停期间验证健康租户仍可写；计划切换验证在恢复传输、两端追平后进行。

哈希场景强杀并重启源节点后重新核对 110 条文档；正常复制场景在两个节点核对 110 条文档，再强杀并重启两端重复核对，并完成计划切换及切换后读取。按成功 ACK 账本核对文档键、修订、载荷、索引查询、multi_get、lookup 和存储 check，差异为零。未知写入修改既有键，恢复后由确认成功的写入覆盖该键；未将未知结果记入成功账本。健康保留场景另核对 100 条文档。

## 回归测试与完整检查

新增两项行为回归：

- `replication_exports_do_not_keep_uncertain_engines_alive` 覆盖下载和交还后的追赶租约。健康时关闭必须 BUSY；故障后不启动过期后台、不 release、不推进副本，也必须在有界重试内重开，保留已确认文档、继续写入、创建新导出并生成准确的 fence 位置。
- `checkpoint_copy_stops_at_a_chunk_boundary_after_wal_failure` 在真实复制任务排队后标记源引擎失败，要求至多完成一个 256 KiB 块即停止；重开后核对完整的 2 MiB 源记录并继续提交。

两项测试移植到未修改的旧生产实现后均失败，在修复实现中均通过。健康下载和追赶跨越 idle 超时的行为另由上述真实服务脚本验证。

首次完整检查还遇到既有 flush 优先级测试的临时文件路径竞态：已完成写入的 `.building` 文件改名后，路径 metadata 可能返回不存在，导致误报。测试现在在输出排队后打开文件描述符，再排入读积压并检查文件长度，避免改名影响观察。连续 5 次通过；在隔离旧源码中将 flush 输出故意降为 Background 后，该断言仍按预期失败，确认没有放松原有回归保护。
