# 存储架构与 v1 格式

## 所有权

`Store` 管理控制目录及有界共享线程池。`TenantHandle` 持有一个租户实例，调用方在嵌入式集成中负责将已授权身份绑定到句柄。HTTP 层提供该校验。活跃句柄或快照即使比 Store 活得更久，仍保留根目录所有权锁，避免第二个管理者同时接管。集合 UUID 和索引 generation 永不根据用户提供的文件路径生成。

```text
root/
  control/LOCK
  control/tenants.json       # 校验封装的注册、配额、生命周期
  control/replication.json   # 节点身份、角色、历史和切换凭据
  control/replication-worker.lock
  control/backup-jobs/       # 远端备份任务与目标指纹，不含业务文件
  tenants/<uuid>/
    TENANT.meta
    LOCK
    CURRENT
    MANIFEST-<uuid>
    wal/<uuid>.wal
    sst/<uuid>.sst
  backups/<tenant>/<backup>/
  backup-work/<job>/         # 独立任务检查点暂存，计入备份暂存预算
  replication-work/         # 按 UUID 分隔的检查点导出/导入暂存
  staging/<uuid>/
  trash/<uuid>/
```

业务数据、索引和 WAL 不跨租户混存。备份执行文件复制，不建立硬链接。目录和文件入口拒绝符号链接。存储根目录应由服务账户独占管理；本地管理员绕过文件权限直接修改数据库不属于 API 授权隔离范围。

OpenDAL 仓库使用独立 v1 备份 manifest 与 COMPLETED 发布协议，不改变 WAL/SST 文件格式。远端对象按租户、持久 generation 和 SHA-256 分开；协议及崩溃边界见 [backup.md](backup.md)。

持久身份由 tenant UUID 与数据库 generation 组成，每个 WAL/SST 头均校验归属。每次打开生成新的 runtime UUID；缓存实例随引擎创建，游标与计划绑定租户、runtime UUID 和快照。恢复后不会复用旧实例缓存。备份恢复保留持久数据库身份，运行代次改变。

v0.5 的节点角色使用相同校验封装持久化，停写或升主先同步角色文件及目录，再对外返回。启用复制时根注册表升级为 v2，旧 Store 不能忽略复制角色以单机写模式打开。业务 WAL/SST 仍为 v1；游标额外绑定复制 epoch，切换历史后失效。

## 键与文档

单套 LSM 使用字节键空间：`C` 集合目录、`D` 文档、`J` 索引定义、`I` 索引条目、`B` 构建增量、`L` Lookup 定义、`G` 删除回收任务。集合 UUID 固定 16 字节；索引键再带 16 字节 generation。可变字符串使用零字节转义和明确终止符。

逻辑读取及 SST 按 `(logical_key ASC, commit_seq DESC)` 排序。内存表以递增提交序号追加每个键的版本，读取时倒序枚举，旧快照与扫描续点以二分定位，刷盘倒序输出；热点键不会在每次写入时搬移整条版本链，也不会在扫描每个版本时重新从头遍历。同一逻辑键最新可见记录决定结果，墓碑同样参与版本比较。序号为每租户递增的 u64；一次原子批次只占一个序号。

DOC1 文档包含类型标记、整数/浮点原始位、UTF-8 字符串、数组元素长度及排序对象字段目录。对象目录保存字段名称、偏移和长度，投影只解码选中字段的值；当前会读取该对象的目录。整数不经浮点转换。字符串、布尔、缺失、null、i64、u64 和 f64 均有独立索引编码域。非负整数在可表示范围内规范为 i64，更大值使用 u64。

保序标量编码翻转有符号整数符号位，浮点使用可排序位变换；`-0.0` 与 `0.0` 同值。降序字段逐字节取反。复合编码连接各个自定界标量。唯一索引键为完整元组，值含 `_key`、`_rev`、匹配字段及覆盖字段；非唯一键在元组后追加 `_key ASC`。

## 原子提交

写入协调器锁内读取 staged 状态、校验 `_rev` 和唯一性，并生成正文、索引删除/写入及构建增量。批次先编码为完整 WAL 记录，再追加 WAL。应用内存表时分块持锁，但新序号直到 fsync 成功后才发布。读者仅使用 committed 序号，因此不会观察半批次。

约 1 ms 的 group commit 窗口允许多个调用共享一次 WAL fsync。后续写者检查的是前序 staged 状态，因此批次内和并发唯一性冲突均可见。WAL 追加或同步失败后返回 `COMMIT_UNKNOWN`，冻结该实例后续写入；该批次可能在恢复后出现。不能把此错误当作未写入并无条件重试。

开启复制后，业务事务还持有节点写屏障的共享许可；计划停写取得排他许可并等待所有已进入事务结束，再固定各租户位置。持久角色为 replica/fenced 时，现有句柄也不能绕过只读。异步从库接收源端原子 WAL 帧，先校验整个页面的身份、连续序号和校验和，再追加本地 WAL 并回放、同步及发布；重启从实际恢复的提交位置继续，没有能先于数据前移的独立应用进度文件。

v0.5.1 将同页已校验的事务帧合并为一次 I/O 队列追加，保留原始帧格式与事务边界。只有所有内存变更完成、WAL 同步成功后才发布页尾序号；未确认的页面遇到截断可恢复完整事务前缀，最后不完整帧仍按原恢复规则处理。主库和从库共用提交统计及目录变更判定，普通文档更新不改变 catalog_seq，避免从库查询计划反复失效。

## WAL、SST 与 Manifest

- WAL 64 字节头：`TKWAL001`、tenant、generation、file UUID、起始序号。记录为 `TXN1`、长度、提交序号、头校验及负载校验，负载包含整个原子批次。
- SST 56 字节头：`TKSST001` 及三组 UUID。数据块按内部键前缀压缩，再用 LZ4 压缩；帧包含压缩长度、原长度、CRC32。每 64 个数据块形成索引分区，文件尾为顶层索引位置及 `TKEND001`。
- Bloom Filter 包含完整逻辑键；非唯一索引额外写入完整匹配元组前缀。过滤器不含提交序号，并包含全部保留版本。只在满足对应匹配边界时启用前缀过滤。
- `TKJ1` 元信息封装包含 JSON 负载 CRC32。新 Manifest 和 CURRENT 使用临时文件、文件 fsync、原子 rename 和目录 fsync 发布。

SST 写入使用 256 KiB 有界顺序缓冲，完成后同步落盘。MultiGet 先对输入逻辑键去重、排序，再为每个候选 SST 二分截取相关键区间，避免逐文件重复处理整批键。SST 数据块按文件/块分组读取，有界并行；顶层目录按层定位候选文件。L0 可重叠，L1 及以上同层不重叠。扫描按层流式打开文件，避免为首屏预读所有 SST。缓存为每租户分片 CLOCK，索引块优先准入，扫描与合并不主动填充普通数据缓存。

单键 Get 使用独立点读路径，无需构造批量键映射。各高层按范围二分定位一个候选 SST，利用文件最大序号跳过不可能更新当前结果的文件；SST 内查找保留跨块、跨索引分区的全部可见版本边界。已排序且唯一的 MultiGet 输入直接沿用顺序，省去再次归并。

SST 点读在块内同时按逻辑键和快照序号二分定位，找到第一个可见版本即结束，包括墓碑；只有尚未找到可见版本时才继续历史块/分区。事务内部读取旧文档与唯一索引也复用该点读路径。

## 刷盘、合并与恢复

刷盘先持久发布包含新 WAL 的 Manifest，再冻结内存表。新 SST 完成 fsync 后发布包含它们的新 Manifest 与 checkpoint，之后才能回收旧 WAL。未发布输出失败可清理并重试；Manifest 发布状态不确定时冻结写入。读取快照持有旧 memtable/文件引用。

复制启用时，已完成刷盘的 WAL 进入 Manifest 的 `retained_wals`，按每租户保留字节窗口淘汰，仍须先持久发布新 Manifest 再删除。保留段不重新参与 checkpoint 之后的恢复回放，但增量传输会检查其文件身份和记录校验。检查点导出清空保留段列表，从库用检查点序号接续增量；超过窗口则重建检查点，不跳过日志。

轮转 WAL 和发布 Manifest 时由写入协调锁保护边界，读取视图保持共享可读；文件同步完成后才短暂取得视图写锁交换内存表。磁盘同步不会占用该视图的排他锁，原有“先持久注册 WAL、后冻结内存表”的恢复顺序不变。

输出文件在集合文档或索引 generation 边界切分，避免不同键空间形成不必要的大重叠范围。合并按 L0 文件压力与各层容量压力选择任务，流式归并到下一层。没有重叠时可只发布文件层级变更，避免重写；仍共享文件生命周期，等待旧读者释放后才回收。保留最老有效快照后的版本及该快照可见的基准版本。只有不会暴露其他文件中的旧值时才清理墓碑。新版本持久发布后，旧 SST 等待最后一个读者释放才删除。

恢复先校验 CURRENT、Manifest、文件身份与引用，再顺序回放 checkpoint 之后的 WAL。仅最后一个 WAL 的不完整尾部可以截断；完整记录校验失败、中间文件截断、缺失文件和序号缺口均失败。孤立的未发布输出在确认有效 Manifest 后清理。损坏租户被隔离，其他租户仍可打开。

## 在线索引

注册 BUILDING generation 与固定快照在同一写入序列中完成。扫描快照分批写入隐藏索引，期间文档修改在自身 WAL 批次中记录 DLT1 二进制旧/新索引条目增量。扫描完成后依序应用增量，在写锁内确认增量已空并发布 READY。查询只使用 `ready_seq <= snapshot_seq` 的 READY generation。

重启后 BUILDING 索引以新 generation 重建；旧输出通过持久 GC 任务清理；GC 保存处理位置，避免每批重新扫描已删除的前缀。失败状态不会提供部分查询结果。同名 FAILED 索引可以重新创建。删除被 Lookup 定义引用的索引会失败，需先删除该 Lookup。

复制从库仅执行物理刷盘/合并，不独立生成索引构建或 GC 事务；它回放源端的相同批次。升主后可以继续原有逻辑维护，避免两边对同一构建生成不同历史。复制协议和切换约束见 [replication.md](replication.md)。

索引基数为构建时统计，普通更新不会维护精确直方图。规划器以主键/唯一匹配、等值前缀、排序和覆盖能力为主要规则，基数只作弱提示；不属于完整成本优化器。

## DSL 与查询执行

DSL 使用有界字节扫描与递归下降解析，生成只含语法和参数槽位的 AST；JSON 字面值由 serde_json 解码。AST 缓存在租户实例内，HTTP 每次请求独立授权，执行时绑定值并调用同一套原生接口。没有单独的 DSL 存储格式或结果缓存。

查询目录缓存以 catalog commit_seq 识别集合和索引定义版本。普通文档更新不改变此序号；集合/索引变更使缓存失效。若游标快照早于当前目录序号，读取快照自身的元信息，不使用当前缓存。迟到的旧读者不会覆盖较新的缓存版本。

v0.5.2 为 Get/MultiGet 单独缓存最近集合的 UUID，不加载索引定义或正文结果。它使用相同的快照与目录提交序号约束，只保留一个计费条目，预算不足则跳过准入；DDL 后重新解析，同名重建不会指向旧文档键空间。

过滤器每次执行编译字段路径和标量常量，IN 预建编码值 HashSet。逐行读取 DOC1 对象目录时借用字段名，验证字段顺序与连续偏移后定位目标字段；标量直接转保序编码，避免解码完整 JSON。存在性判断不解码字段子树。投影仍按源容器形状组装结果，严格类型与缺失/null 的比较语义保持一致。

游标指纹由集合及绑定后的 filter/sort/select/limit 生成，不需要克隆整个 Query。JSON 响应大小通过计数写入器计算；Lookup 去重结果同时保留编码长度，在恢复重复输入位置前检查并预留输出预算。

排序字段路径在每次查询开始时编译，逐行直接读取保序标量编码，降序字段反转编码字节。完整文档 Top-K 在候选阶段保留带预算的二进制引用，仅对最终页解码；窄字段投影仍立即生成紧凑候选，避免为少量输出长期引用大正文。候选、最终文档和输出字节继续受预算检查。

游标在结果准备成功后，于同一游标锁内校验仍存在、消费旧 token 并发布新 token。并发续页只能有一个调用成功；已经被消费、释放或到期的 token 返回 CURSOR_EXPIRED，失败的查询不发布下一页。

## v0.6 时态记录与读取调度

`identity_temporal` 是受管业务集合，记录仍使用 DOC1；entity、timeline、history、head、knowledge、operation 与现有文档共用租户 LSM。历史键包含标识 SHA-256 和降序知识 ordinal，知识 UUID 永不按 ordinal 重建。所有时间线、历史、实体绑定修订、知识头及幂等收据同批 WAL 提交；不复用短租约 MVCC 版本充当永久知识历史。完整约束与升级限制见 [identity.md](identity.md)。

无变更事务若读取到了 group commit 中的 staged 数据，也必须等待相应提交序号持久化；命中收据不意味着可以提前确认。I/O 失败仍返回 COMMIT_UNKNOWN 并停止继续写入。

长范围扫描从第二个数据块起，在单分区、范围边界内每个 I/O 工作项最多解码四个连续块。首块、点读和带前缀过滤的 Lookup 仍按需读取。额外预读不主动驱逐缓存；内存不足时使用已完成前缀继续推进。读取统计包括已经预读但尚未消费的块。固定 Lookup 共享计费的 Arc 执行计划，并复用按提交序号校验的集合身份缓存。

复制应用将相邻小事务按最多 8 条记录合并插入内存表；已有较大事务保持原有最多 64 条分段，避免每个小事务都重新交接读写锁，同时保持每段短暂持锁。该缓冲在 WAL 追加前按预算预留；原始事务序号、WAL 帧和整页持久化后发布规则不变。

## v0.7 中间件元信息

根注册表为 v3，独立记录 replication_enabled，升级不会丢失旧 v2 的角色丢失保护。TENANT.meta/注册表新增 history UUID；本地恢复和远端备份导入生成新 history，在生命周期日志中与目录切换一起发布。复制安装保留源 history；WAL/SST 文件归属 generation 不因此改变。旧租户缺省 history 使用原 generation 作兼容标识。

租户键空间增加 R（按集合 UUID、主体与操作 ID 保存原子写回执）、S（集合冻结标记）、P（资源当前版本指针）及 V（版本发布记录）。这些业务元信息与正文保存在同一租户 WAL/LSM，不进入控制目录。冻结检查在写事务内部；所有索引完成后才允许发布。旧回执与发布版本的保留策略见 [中间件契约](middleware.md)。

## v0.8 保留元信息

根注册表升级为 v4，复制协议为 3，旧程序拒绝打开。租户 LSM 使用独立 `~` 命名空间保存策略、GC 进度、截止时间有序索引、重试 token、发布回执、集合引用与知识 ordinal 索引；各键前缀有独立边界，不能与策略自身重叠。到期标记、分批删除和进度同批提交；不直接移除活动 SST。迁移仅扫描相关元信息，历史扫描为每个标识保留前驱基线。

新租户创建复用 registry v4 的 Restoring 生命周期：数据先在 staging 完成并同步，发布含 stage/old UUID 的 journal 后再切换到 tenants，并最终持久化 Active。未发布阶段可回收，已发布阶段可在启动完成；未增加磁盘格式或协议版本。旧版本未注册目录仅在确认空库且无人持有时自动回收，有数据或无法确认的目录不会自动删除。
