# v0.9 通用 KV 能力验证

日期：2026-11-05。验证环境：OrbStack Ubuntu、Linux aarch64、Rust 1.90。交付是本地源码、Linux 程序、OpenAPI、文档和示例，不包含线上部署。

## 实现范围

| 能力 | 已完成的行为 |
|---|---|
| 条件批次 Check | 在任何修改前校验版本/不存在；不更新被检查记录；与修改及回执共用原子提交 |
| read_batch | 同租户跨集合 Get/MultiGet/Query 共用快照；点读合并为一次存储 MultiGet；整批扫描、耗时、响应及结果内存预算 |
| 通用数据集发布 | 无 Lookup 也可冻结发布；按实际版本读取；Query 游标绑定资源/版本并支持续页 |
| 兼容与集成 | HTTP/OpenAPI、能力发现、可运行 Rust 示例；原 Lookup 与身份 API 保持兼容 |

检查条件面向批次之前的状态；Put/Delete 维持原来的顺序语义。批次重试先命中有效回执，不因条件后来改变而错误重做。现有租户保留期、历史标识、备份及异步复制机制继续复用。

## 实际运行结果

- `cargo test --locked --features failpoints -- --test-threads=1`：**101 项通过**，在既有 94 项上新增 7 项集成回归。覆盖 WAL/Manifest 崩溃恢复、回收边界、快照、索引、租户隔离、备份恢复、时态和主从切换。
- 最后调整无 Lookup 元信息的序列化后，重新执行 middleware / replication：**28 项通过**。持久数据仍显式保留空 lookup 字段，使旧版本能够解析新发布元信息。
- `cargo clippy --locked --all-targets --features failpoints -- -D warnings` 与格式检查通过。
- release 服务及恢复工具构建通过；实际运行新 Rust 示例，完成一致读取、条件更新、幂等重放和固定数据集版本读取。
- 实际启动 release HTTP 服务，通过新增接口工作流、原生 HTTP、DSL、时态身份和统一保留脚本。新发布数据经备份、恢复及进程重启后继续可读。
- OpenAPI 3.1 第三方规范校验通过，**62 个路径、83 个组件 schema**；实际 ReadBatchResult、PublishedLookup、PublishedReadBatch、PublishedQuery 响应通过 JSON Schema 校验。
- 在隔离测试目录中，以真实 v0.8.1 程序打开 v0.9 创建的数据，确认可读取新发布元信息、正文并拒绝修改冻结集合，再切回 v0.9 读取。此项只验证上述兼容边界，不代表完整降级资格认证。

## 新增回归保护的边界

1. Check 即使出现在 Put 之后，也检查批次前的状态；失败不留下前序修改；Check 不改文档修订；持久回执跨重启重放。
2. 并发原子写期间，组合 Get、MultiGet 和 Query 不混合不同版本；Query 续页维持原快照。
3. 多次查询不能分别重新取得扫描预算；失败批次释放已创建游标；并发名额为 1 时不会被内部嵌套调用重复占用。
4. 重复点读的返回数据累计超限、累计结果内存超限会明确失败，不因每个子请求单独合法而绕过预算。
5. 发布切换和旧版本到期后，已获准游标仍在租约内读取旧快照；新请求不能重新访问过期版本；错误资源/版本不能复用游标。
6. HTTP 新入口继续执行租户和读写角色校验；只读主体不能提交 Check 批次或发布数据。
7. 条件写回执、无 Lookup 发布版本随 WAL 复制；主从切换后可按原操作重放，发布数据保持可读。

## 未改变或未验证的边界

原子写仍限同租户同集合；组合读取不等于跨集合写事务。Schema 含义、来源优先级和同步完整性由业务层负责。本轮没有新增集合 Validator、集合级权限、业务 CDC 或多语言 SDK。

复制仍为异步，不承诺故障升主零数据丢失；游标不跨重启。未执行真实掉电、真实云 S3、新一轮百万/千万数据性能压测或多日持续负载，不据此宣称性能目标或完整生产可靠性已获验证。
