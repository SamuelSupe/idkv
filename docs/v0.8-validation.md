# v0.8 统一历史保留验证

本版交付租户级单一 `retention_seconds`。当前文档、发布版本、知识头和时间线不失效；被覆盖的发布/知识从覆盖时计时，普通、时态和发布回执从提交事务记录时间计时。详见 [配置、重试和迁移契约](retention.md)。

## 正确性与故障回归

OrbStack Ubuntu AArch64 / Rust 1.90 下，完整 `cargo test --locked --features failpoints -- --test-threads=1` **92 项通过**；全目标严格 Clippy 与格式检查通过。发布程序为不含 failpoints 的正常构建。

新增回归保护以下行为：

- 回执到期前相同请求返回同一生成键；不同内容冲突；到期及回收后请求均不重复执行，重启后仍拒绝。
- 缩短策略不能在原 token 仍能首次提交时先清掉回执，避免旧请求重新执行。
- 新增回执元信息不减少公开的 1,000 条文档批次容量。
- 当前发布超过保留时长仍可读；只有被替代后才开始计时；多个资源共享冻结集合时，最后一个保留引用消失才删除集合。
- 连续 **1,050 次**发布并回收，最终只保留当前集合，能持续越过原 1,024 集合上限，收尾回收滞后为 0。
- 旧快照在发布退役、集合删除和合并后，仍可以读原正文并通过原索引执行 Lookup。
- 时态历史保留跨越边界的前驱基线，空时间线不导致旧绑定重新出现；当前实体、时间线与知识头保留，后续覆盖才设置截止时间。
- 策略/凭据随检查点恢复；恢复回退后，缺失回执的旧历史请求被拒绝。
- 双节点复制策略与回收状态、从库保留当前数据、计划切换后拒绝过期重试；既有日志过期检查点重建与复制故障测试继续通过。
- 回收进度提交前、已持久提交后分别中止进程，重启接续清理，已确认当前数据不丢失、不重复写。
- 注入在线磁盘预算达到用户写入门槛的状态，前台写入背压时维护事务仍可使用预留空间提交删除；不绕过租户总预算。这是预算边界测试，不是真实磁盘写满测试。

## 持续回收与读延迟检查

单机 OrbStack、8 活跃租户 + 32 冷租户、8,000 条约 1 KiB 驻留文档、每集合 3 个索引、2 写线程、16 读线程。每写批次 20 条，并持久化操作回执；读取循环检查正文、批量可见性和唯一索引。全局引擎预算 512 MiB，每租户 64 MiB。读循环有 1 ms 间隔。

每种模式主测量窗口 60 秒，顺序执行，期间没有并发构建或测试套件。线程工作量还包含并发创建冷租户阶段，不将其直接换算为稳定 QPS。收尾等待统一保留期及额外 1 秒，然后检查回收状态、刷盘、合并、校验，并关闭重开核对全部 8,000 条当前文档。

初始实现每轮最多清理 16 条小型到期元信息：同样负载中产生超过 25,320 条回执，收尾只回收 17,664 条目标记录，仍有积压。调整为每轮最多 64 条小型到期元信息；大块时态历史与迁移扫描继续限制为 16 条，并随原子预算下调。加入 next_expiration_ms/expiration_lag_ms 状态字段，直接验证排空。

| 观测 | 持久回执、不回收 | 最终版、统一保留 3 秒 |
|---|---:|---:|
| 完成文档更新 | 390,280 | 518,600 |
| 完成读取 | 412,440 | 414,554 |
| 写线程背压次数 | 2,452 | 0 |
| 热点读线程各自 P99 范围 | 82–85 µs | 75–82 µs |
| 其他读线程各自 P99 范围 | 11–12 µs | 10–11 µs |
| 引擎预算计数峰值 | 36,972,186 B | 36,982,922 B |
| 进程 VmHWM 采样 | 58,777,600 B | 54,517,760 B |
| 逻辑回收目标记录数 | 不适用 | 26,012 |
| 收尾过期队列 | 不适用 | 空，滞后 0 |

基线有一次采样捕获 L0 积压导致的 RESOURCE_EXHAUSTED 维护背压；最终保留模式没有该采样事件。两种模式均未记录租户不可用或其他维护错误，重开正确性检查通过。26,012 包括回执和重试凭据，不是被删除的业务文档数；逻辑回收数也不是释放磁盘字节数。

这些是单轮短时、固定驻留数据的观测。工作量和 P99 变化不作为稳定吞吐提升或生产延迟 SLA；它们用于确认本负载中回收能够追上写入，并未观察到明显读尾延迟恶化。不是百万条驻留数据、数日稳态或任意并发量的资格验证。

## 交付边界

- 根注册表 4、复制协议 3，必须共同升级主从；旧节点不能混跑。启用回收前调用方要接入 retry_token，新发布消费者使用响应顶层 version。
- 未配置保留的租户保持原行为；启用后本版不提供关闭接口。变更不调整已固定期限，恢复不重置期限。
- 物理释放仍受有效快照、合并和设备可用空间影响。冷租户再次打开后继续后台清理；截止时间读取检查不等待物理回收。
- 当前完整时间线仍有 1,000 段限制。本轮没有按业务时间裁剪当前状态，也没有增加长期审计归档。
- 没有本轮真实 S3、独立物理机器/设备故障、真实掉电或数日持续负载验证。异步复制可能丢失未复制提交的契约不变。
