# v0.7 中间件集成与可观测性验证

本轮完成安全接入与集成契约，并加入独立可开关的指标、OTLP 链路和日志。交付是本地源码、Linux AArch64 程序、OpenAPI 与归档，不包含线上部署。

## 修复与新增行为

- CAS 绑定数据历史与复制 epoch，本地恢复和导入轮换历史；正数裸版本号明确拒绝。
- HTTP 不再按最大请求/响应包大小为每个小请求预留数十 MiB；接收、解析、序列化分别按实际分配计费。
- 普通 put/delete/batch/DSL 写入可持久化重试回执；生成主键、正文、索引和回执同批提交。
- 认证使用稳定 subject；新增 identity_write/identity_correct，密钥轮换不改变同主体的回执身份。
- Lookup 发布以不可变集合和 UUID 版本为单位，原子切换当前指针，排队消费者可固定历史版本。
- HTTP 客户端发现主库、在从库等待已确认写入并安全重试；历史不匹配不会自动降级一致性。
- 注册表 v3、复制协议 2 明确阻止旧节点接入新语义；需要主从共同升级。
- 增加读/写 readiness 和 SIGTERM 排空；指标、OTLP 链路与日志互相独立，队列和并发有界。

## 源码与故障验证

OrbStack Ubuntu AArch64 / Rust 1.90 下，`cargo test --locked --features failpoints -- --test-threads=1` **81 项通过**；全目标严格 Clippy 和格式检查通过。完整日志见 `../bench-results/v070-final-tests.log`、`v070-final-clippy.log`，具体环境见 `v070-final-environment.json`。

新增回归覆盖恢复后数值版本复用、缺失历史拒绝、写后响应受限的明确结果、普通写回执跨重启/切换、同 ID 不同输入冲突、WAL 同步和刷盘故障后生成键与回执一起恢复、不可变发布及旧版本保留、小请求跨租户预算、主体轮换、纠错权限、readiness、旧复制协议拒绝、客户端切换和最小已应用位置。

已有随机查询、动态类型、覆盖索引、快照、在线建索引、恢复、备份、时态身份、复制并发及故障测试继续通过。双进程发布版和故障注入版验证从库 SIGKILL/重启、断线追赶、双向计划切换、日志回收后的重新初始化、旧角色配置重启及明确确认的故障升主。它们仍是单个操作系统里的进程故障测试。

## 前后实测

对同一配置（全局 256 MiB、租户 128 MiB）运行三个约 85 字节、等待未来复制位置的小请求，然后让另一租户写入；两版分别使用独立数据目录。

| 场景 | v0.6.1 | v0.7.0 |
|---|---:|---:|
| 等待期间记录到的预留内存 | 218,127,378 B（约 208 MiB） | 7,186 B（约 7 KiB） |
| 另一租户的小写入 | 429 | 200 |
| SIGTERM 退出码 | -15 | 0 |
| SIGTERM 时在途等待 | 连接直接断开 | 等待结束，返回 409/REPLICA_LAG |
| 排空用时 | 不适用 | 约 1.06 秒 |

旧程序也实测拒绝打开 v3 根目录。原始结果：[边界前后对比](../bench-results/v070-boundary-comparison.json)。这张表是引擎预算计数，不是进程 RSS；旧版 `/v1/metrics` 自身的固定预留也包含在当时读数内。

同次运行的 500 次顺序 loopback HTTP Get 中，最终交付二进制的 P99 为 0.155 → 0.167 ms（增加约 0.012 ms），P50 为 0.069 → 0.072 ms。此前一次试跑的 P99 方向相反，本轮不宣称 HTTP 尾延迟改善或排除小幅回退。这里只用于发现毫秒级异常，未做多轮隔离统计；不据此宣称嵌入式引擎提升、持续吞吐或生产延迟 SLA。HTTP 连接开销、宿主调度和缓存状态都会影响结果。

## 观测与 HTTP 验证

- 单测用本地 OTLP HTTP/JSON 接收器验证 traces/logs 四种组合，包括全关；检查父 trace ID、日志关联和不导出凭证/正文/文档键。
- 接收端不可达且队列仅 16 条时快速产生 1,000 次观测，请求侧不等待网络导出；这是有界行为验证，不是 exporter 稳定性压测。
- 正式服务二进制带 `--telemetry-config` 运行：metrics 关闭时两个指标接口 404，traces/logs 开启时真实发送两种 OTLP 请求；校验 HTTP span 的父 span 和日志 span ID 相同。SIGTERM 后正常关闭。证据：[CLI 观测验证](../bench-results/v070-cli-telemetry.json)。
- 默认指标开启时验证 Prometheus Content-Type、请求耗时直方图、查询 I/O 计数及当前引擎统计。
- 原生 HTTP、DSL、时态身份和 OpenDAL filesystem 备份/恢复流程通过；OpenAPI 3.1 静态规范校验通过，归档二进制导出的 schema 与交付文件一致。

## 仍然保留的边界

没有实测生产 Collector/Grafana/Tempo/Loki 平台，也没有本轮真实 S3、物理掉电、独立设备故障或数日高负载资格验证。异步主从的故障升主仍可能丢失未复制提交，不包含自动选主、共识或外部 fencing 自动化。

遥测是有界、尽力而为的导出，队列满或采集端失败可能丢弃记录；不作为零丢失审计。SDK 导出队列不属于引擎 memory_bytes 计数，容量由独立 queue_size 上限控制。当前自动观测覆盖 HTTP 适配器，宿主嵌入式函数需显式接入。

普通写回执保留到集合删除；发布版本保留到租户删除，尚未实现 TTL/版本清理。注册表 v3 不能直接由旧程序打开，凭证需增加 subject，旧 v0.6 时态回执的主体迁移限制详见 [中间件契约](middleware.md)。
