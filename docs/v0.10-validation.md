# v0.10 请求级读取控制与客户端验证

验证环境：2026-11-06，OrbStack Ubuntu Linux AArch64，Rust 1.90。实现范围是请求级读取控制和主从 HTTP 客户端读取接口补齐，持久格式仍为注册表 v4、WAL/SST v1、复制协议 3。

## 完成内容

- `ReadOptions` / `TenantReader`：收紧超时、扫描上限，拒绝集合全扫描，支持协作式取消。Query、Lookup、组合读取、发布版本读取共用明确的截止时间；批次内扫描量累计。未受控的主键 Get 保留原专用路径。
- 存储扫描在物理记录间检查取消；MultiGet 保留批量去重、按块分组和有界 I/O，并在文件、分区及块读取边界检查。没有为每个输入键创建任务。
- HTTP 通过三个控制头传参，拒绝错误、重复以及写入/管理路径上的控制头。DSL 只读执行复用相同预算。handler future 结束时通知阻塞读取消。
- Rust Client 补齐 MultiGet、Query、Explain、Lookup、read_batch、发布元信息及发布 read/query/lookup、游标释放。发现、回退、响应读取使用同一客户端总预算；并发发现最多两个配置节点，保留执行时间。
- 普通、组合和发布查询的 SDK 游标绑定原节点及租户；续页和释放都不跨节点重试。最低位置落后可换主库；预算、历史、权限及续页失败明确返回。
- 新节点确认 `request_read_controls_v1`。客户端验证响应确认，防止旧节点静默忽略限制；原始 HTTP 使用者须先升级节点并检查 capabilities。

使用契约及示例见 [读取控制](read-controls.md) 和 [可运行示例](../examples/read_controls.rs)。

## 发现并修复的边界

1. **旧快照不满足新最低序号**：原 HTTP 一致性等待只检查节点是否追平，随后可能用更早的游标快照返回数据。现在在消费游标前检查快照序号，返回 SNAPSHOT_TOO_OLD，并保留原游标。真实主从追平后验证此场景，普通续页仍保持旧快照。
2. **只读客户端无法主动释放游标**：DELETE 游标此前落入管理角色默认分支。现在 read 角色可释放其授权租户的游标；跨租户释放仍被拒绝，已释放游标不能续页。
3. **客户端错误回退可能绕过资源限制**：旧 Get 将 RESOURCE_EXHAUSTED 纳入回退；新读取路由直接返回预算错误，不通过另一节点重做。历史冲突同样保持终止语义。
4. **write_context 的双主检查不一致**：现在与 write_batch / retry_context 一样，发现两个可写节点时返回 REPLICATION_CONFLICT。

## 实际验证

- 完整 failpoints 回归 **109 项通过**，覆盖 WAL、恢复、合并、快照、索引、回收、备份和复制切换。最后修正游标释放角色后，全部 HTTP、middleware、replication 测试再次运行，**36 项通过**。
- 新增四项行为回归，覆盖请求限制不能放宽引擎上限、历史版本计费、OR 全扫描拒绝、失败游标可继续、批次失败释放游标、请求取消不影响其他操作；DSL/HTTP 控制头及共享等待截止时间；完整客户端读取和所有游标形式；预算不回退、能力不兼容、超时/取消、慢节点发现和续页不回退。
- 扩展已有存储版本链测试验证扫描中途取消且快照仍可读；扩展 HTTP 租户边界测试验证只读游标释放与跨租户拒绝。没有用测试专用路径替代真实主从 HTTP 读取。
- 最终代码通过 `cargo clippy --locked --all-targets --features failpoints -- -D warnings`、格式检查及 release 构建。
- 最终 Linux 服务实际运行原生 HTTP、DSL、时态身份和统一保留脚本，验证发布/读取、备份恢复及重启；新控制头、旧快照最低位置拒绝通过。OpenAPI 3.1 校验通过，**62 个路径、83 个 schema**，实际响应通过 JSON Schema 校验。
- v0.9.1 程序可打开新版本写出的同格式数据，读取发布元信息及正文并保持冻结集合不可写，再切回 v0.10 继续读取。新客户端对旧节点仍会按能力契约拒绝；这不是任意版本混跑或完整降级资格认证。
- 新增 Rust 示例实际执行嵌入式控制、HTTP 客户端分页、只读凭证释放游标及取消。Linux AArch64 二进制、OpenAPI 与 SHA-256 清单同步更新。

## 限制

截止时间和取消是协作式机制，不能强制中断已经进入的系统 I/O，也不能回滚写入。HTTP 断开是否立即释放 handler 取决于运行时；本轮验证 handler future 被取消后释放等待任务，以及客户端超时/取消，未验证所有代理和网络中断组合。

跨节点传输失败后，客户端无法精确累计丢失响应尝试的扫描量；max_scan 是每次服务端执行的上限。分页响应丢失后不自动重试；丢失的服务端快照依赖租约回收。

本轮没有开展新的百万/千万条、多日运行、真实掉电、真实云 S3 或正式 P99 性能资格测试，不据此宣称性能提升或生产 SLA。复制仍是异步一主一从，既有故障升主 RPO 边界不变。没有远程部署或发布 Git 标签。
