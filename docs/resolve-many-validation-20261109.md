# resolve_many 与 DSL 实现验证（2026-11-09）

> 本记录测量的是主体反查/历史功能加入前的 resolve_many 阶段。后续主体功能将注册表/复制协议提升为 6/4，当前兼容与验证范围见 [主体查询验证](subject-queries-validation-20261109.md)。

实现基于 b006c00 工作树。新增原生批量时态解析、HTTP 端点、Rust HTTP 客户端，以及 `resolve with $request` / `resolvemany with $request`。使用契约见 [identity.md](identity.md) 和 [dsl.md](dsl.md)。存储格式、复制协议及既有单条解析响应结构保持兼容。

## 执行与资源边界

整批先校验输入，再取得一个租户请求许可、一份快照和一个知识版本。按完整标识校验摘要分组，保留输入下标和事件时间；latest 以最多 8 个不同标识一组复用 MultiGet，固定知识使用有序、不重叠的历史前驱范围扫描。每条时间线解码一次，用二分定位每个事件时间。当前组的解码临时内存及时释放，输入、分组和输出内存计费至调用结束。

调用共享截止时间、取消和累计扫描预算；历史扫描计入墓碑。知识过期、恢复回退、未知版本或预算失败不返回部分结果。返回前复核快照和 history。DSL 只缓存语法，不缓存参数、知识头或解析结果。HTTP 权限仍由 URL 租户和凭证决定。

## 实际验证

环境：OrbStack Ubuntu 25.10 ARM64，Rust/Cargo 1.90.0；工作目录共享自 macOS。测试和示例在 Linux 执行。

- `cargo test --all-features --no-fail-fast`：281 项通过，0 失败；包括真实进程崩溃恢复、复制与切换、HTTP、身份、DSL、保留和资源控制回归。
- 新增/扩展回归：输入顺序和重复项，缺失标识，半开区间端点，固定历史知识，Prepared 绑定更新与跨租户复用，非法输入整批失败，累计扫描限制，历史墓碑，取消/截止时间，临时内存和响应上限，以及失败后快照/内存释放。
- 并发修正：12 个标识在一次事务中更新，读取包含 240 个事件；多轮并发更新中每批保持一致，再以返回知识 UUID 重读并逐项比较。
- HTTP 与真实双节点客户端：只读凭证可调用原生和 DSL 解析，跨租户请求拒绝；尚未复制的知识 UUID 明确不可用，最低位置等待受截止时间约束，追平后结果与主库一致。
- 保留与恢复：过期但尚未 GC 的知识和已回收知识都拒绝；恢复回退丢弃的知识 UUID 不会被复用。
- `cargo clippy --all-targets --all-features -- -D warnings`、`cargo fmt --all -- --check`、`git diff --check` 通过。
- `examples/identity.rs` 实际运行，核对单条、批量和 DSL 在修正前后及区间端点的归属。

最终还对单条请求复制前的输入验证作了加固，随后重跑 identity、DSL、HTTP 测试和 Clippy。没有将静态检查当作运行验证。

## 相同负载对比

命令：

```sh
cargo run --locked --release --example identity_resolve_many -- /var/tmp/identity-batch-new 20
```

使用同一已确认数据集，对每份输入交替测量 N 次单条解析和一次原生批量解析。每组 20 轮，比较全部结果；DSL 结果也与原生批量逐项核对。共 48 组，覆盖批量 1/32/128/1000、1000 个不同标识或循环使用 8 个标识、1/64 片段时间线、latest/固定当前知识 UUID、16 MiB 块缓存/禁用块缓存。下表为全部测试结束后单独复测的 1000 条负载，耗时单位毫秒。

| 块缓存 | 标识 / 时间线 | 知识模式 | 逐条 p50 | 批量 p50 | 逐条 p95 | 批量 p95 |
|---|---|---|---:|---:|---:|---:|
| 16 MiB | 1000 个不同标识，各 1 片段 | latest | 4.070 | 2.309 | 4.791 | 3.252 |
| 16 MiB | 1000 个不同标识，各 1 片段 | 固定 UUID | 41.301 | 4.469 | 75.437 | 8.569 |
| 16 MiB | 循环 8 个标识，各 1 片段 | latest | 3.643 | 1.205 | 4.103 | 1.381 |
| 16 MiB | 循环 8 个标识，各 64 片段 | latest | 16.476 | 1.328 | 16.967 | 1.373 |
| 16 MiB | 循环 8 个标识，各 64 片段 | 固定 UUID | 83.432 | 1.840 | 96.552 | 2.144 |
| 禁用 | 1000 个不同标识，各 1 片段 | latest | 96.262 | 7.564 | 114.614 | 10.420 |
| 禁用 | 循环 8 个标识，各 64 片段 | 固定 UUID | 162.861 | 2.106 | 170.610 | 2.219 |

1000 个不同标识的逻辑文档读取从 2000 次降为 1001 次；循环 8 个标识时降为 9 次。64 片段、固定 UUID、16 MiB 块缓存场景的块读取从 4750 次降为 38 次。这是共享知识头、去重及复用历史扫描状态的效果。

这些数据比较当前版本的逐条调用和批量调用，并非旧版本到新版本的整体性能对比。20 轮仅用于本机微基准，p95 对调度波动敏感。禁用引擎块缓存仍使用 OS 页缓存；未测物理冷盘、网络端到端吞吐或长期生产混合负载，不据此推断生产容量。每次仍需解码一条完整时间线，长时间线及很大的返回结果仍受预算限制。

原始测试输出和 JSONL 保存在 Linux `/var/tmp/idkv-resolvemany-*.log`、`/var/tmp/idkv-resolve-many-bench-20261109-b.jsonl`，不加入仓库。可用上述程序重新生成。
