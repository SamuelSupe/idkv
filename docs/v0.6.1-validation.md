# v0.6.1 性能优化与稳定性验证

日期：2026-11-05。基线为已交付 v0.6.0，候选为 v0.6.1。结果来自同一 OrbStack Ubuntu VM，以下数值均为本轮重新测量，不与上一轮不同时间的结果直接相减。

## 结论

时态解析的主要收益来自减少解码分配，1000 片段当前解析 P99 降低约 65.8%，固定当前知识 UUID 降低约 50.8%。固定每秒 10000 次读取时，复制追赶中位数缩短约 9.6%，Lookup P99 降低约 38.7%；无限速读压下追赶时间基本持平，P99 上升约 7.5%，读取吞吐中位数下降约 10.2%。不能将本轮表述为所有复制负载均有改善。

## 修改与边界

1. WAL 发送原来逐帧分别读取头部与正文。现在对当前文件复用最多 64 KiB 顺序缓冲，限制在请求捕获的文件前缀；逐帧长度、序号及校验不变。缓冲计入租户及全局预算。必需帧或 base64 输出需要空间时，释放预读并从准确位置继续，避免预读挤占必需读取。
2. 内存表直接接收暂存记录的所有权，省去第二次键分配及值引用计数增加。保留一次树查找；实验中的“先查找、再插入新键”方案没有保留。小事务 8 条、大事务 64 条的锁分段保持不变，整页仍在 WAL 同步完成后发布可见序号。
3. 原先每个日志页后都重新获取并解析整节点状态、校验租户目录。现在最多复用 8 轮；在轮次边界发现已耗时 10 ms 即重新刷新。每轮每个待追赶租户一页，每页独立验证源历史及租户存储代次。后续页面使用上一页报告的最新源位置，避免持续写入时将合法推进误认为历史分叉。10 ms 是轮次间刷新条件，不是网络请求或一整轮的硬耗时上限。
4. 时间线和知识记录直接从 DOC1 解码为固定 Rust 类型，去掉中间 JSON 树及对象目录字符串分配，复用现有快照感知集合身份缓存。动态实体属性、幂等收据及普通文档仍使用原解码路径。严格保留类型、字段、深度、偏移、UTF-8 与有限浮点校验；没有加入结果缓存，也没有改磁盘或传输格式。

本轮没有改成只读取一个时间段：第一阶段仍解码整条时间线，写入仍保存完整历史；原生批量前驱查询及反向覆盖索引属于后续阶段。临时内存保留保守计费，不能从时延下降推断预算需求同比下降。

## 环境与方法

OrbStack Ubuntu / Linux AArch64，18 vCPU、约 31.4 GiB 内存，Rust 1.90；数据位于 /var/tmp 的虚拟 Btrfs 磁盘。性能测试与本轮编译、功能运行及持续负载分开执行。没有做固定 CPU 绑核、裸机 NVMe 或独立双机资格验证。

每个场景三轮，顺序为 前→后、后→前、前→后，表格为三轮中位数。复制基准新增源状态/日志请求计数，同一个增强后的基准分别链接 v0.6.0 原始源码和 v0.6.1。其他基准源码相同。初始化与数据加载不计入查询/追赶时延。保留全部原始结果及较慢候选，不挑选最好的一轮。

## 时态解析

每组 1000 次，分别构造 1、10、100、1000 个交替实体片段，刷盘、合并后暖读；每次校验实体正确且身份文档读取为 2 次。fixed_current 固定当前知识 UUID，fixed_earlier 固定构造到约一半时的历史知识。

| 片段数 | 模式 | 前 P95 μs | 后 P95 μs | 前 P99 μs | 后 P99 μs |
|---:|---|---:|---:|---:|---:|
| 1 | latest | 4.291 | 2.459 | 4.792 | 3.000 |
| 1 | fixed_current | 4.375 | 2.875 | 5.541 | 3.583 |
| 1 | fixed_earlier | 5.000 | 2.958 | 6.250 | 3.542 |
| 10 | latest | 9.541 | 4.833 | 10.875 | 5.625 |
| 10 | fixed_current | 11.084 | 4.917 | 13.500 | 6.167 |
| 10 | fixed_earlier | 7.750 | 4.083 | 9.375 | 4.958 |
| 100 | latest | 122.876 | 52.209 | 143.917 | 60.667 |
| 100 | fixed_current | 120.667 | 91.542 | 131.875 | 104.041 |
| 100 | fixed_earlier | 101.834 | 78.584 | 114.375 | 88.792 |
| 1000 | latest | 629.168 | 210.209 | 661.461 | 226.417 |
| 1000 | fixed_current | 795.085 | 397.793 | 883.502 | 434.376 |
| 1000 | fixed_earlier | 462.376 | 264.751 | 480.043 | 285.209 |

1000 片段 latest 仍为 0 次物理块读取、2 次文档读取；fixed_current 仍读取 4 块并解压约 1.41 MB。收益主要来自 CPU/分配路径，未通过减少需要返回的结果或跳过历史校验取得。

## 复制追赶

主库先由 4 个写线程形成积压，再启动从库追赶；从库用独立线程持续 Lookup。追平后逐条核对 1024 个热键及轻租户数据。固定到达率使用同一单调时钟和到达序号，服务时间不包含基准生成器的定时等待。该实验不是持续主库写入吞吐测试。

| 16384 提交 / 16 读线程 / 10000 次每秒 | 状态请求 | 64 | 19 |
| 16384 提交 / 16 读线程 / 10000 次每秒 | 日志请求 | 65 | 65 |
| 8192 提交 / 4 无限速读线程 | 追赶 ms | 205.177 | 205.115 |
| 8192 提交 / 4 无限速读线程 | Lookup P95 μs | 5.250 | 5.125 |

固定速率下状态请求减少约 70.3%，日志页数相同；无限速下状态请求减少约 71.9%。这是实际请求计数，不是估算。读取 P50/P95 未表现出与 P99 相同幅度的改善。

## 正确性和运行验证

- 完整 73 项测试通过；failpoints 开启、单测试线程。严格 Clippy（全部 targets、警告视为错误）及格式检查通过。
- 新增解码差分回归：对边界整数、字符串、可空数组、未知字段逐字节截断和变异，与原 JSON 解码结果/拒绝行为比较。
- 新增 WAL 缓冲回归：大于缓冲的事务、跨缓冲记录、精确游标继续、固定可见文件前缀、低预算回退、截断及校验错误。
- 新增主库持续推进/多租户追赶回归；原有快照、正文索引原子性、畸形整页拒绝、WAL 恢复、幂等持久化及身份历史测试全部通过。
- 正式二进制双进程：初始化、4000 文档更新、覆盖 Lookup、从库 SIGKILL/重启续传、双向计划切换、旧配置重启、显式故障升主。
- 故障二进制双进程：复制 WAL 撕裂、持久停写后崩溃、升主发布后响应丢失，均通过恢复与重试验证。正式 dist 使用未启用 failpoints 的二进制。
- v0.6.0 主库 + v0.6.1 从库：普通集合、当前/历史知识 UUID、切换后原幂等收据、双节点重启及切回通过。身份示例需要双方至少 v0.6；不支持旧版忽略受管集合保护后写入。
- HTTP 原生接口、DSL、时态鉴权/错误边界、OpenDAL fs 备份恢复通过；OpenAPI 3.1 校验通过（50 paths / 62 schemas）。

## 持续运行

180 秒，8 个活跃租户与 32 个冷租户、2 个写线程、16 个读线程、3 个索引。完成 1,515,200 次文档更新和 1,211,066 次读取；未观察到租户故障或后台维护错误。关闭重开后再次核对全部 8 个活跃租户、8000 条文档、索引和批次可见性。具体计费与 RSS 数据见 [持续运行汇总](../bench-results/v061-soak-summary.json)。

引擎计费峰值 35,844,058 字节（预算 536,870,912 字节），Linux VmHWM 采样峰值 62,533,632 字节；两者口径不同，不相互替代。

功能进程验证与持续运行的开始阶段同时执行，以上吞吐只说明完成工作量，不是前后性能对比。180 秒不足以证明长期稳定性；未验证真实掉电、独立磁盘故障、真实跨机网络、真实 S3 服务、千万级/数据大于内存三倍场景，以及 macOS 原生二进制。
