## 逐项结论

| 报告项 | 核实结果与处理 |
|---|---|
| 1. WAL 尾部完整长度、魔数/CRC 错误不能打开 | 实现属实，但“必定未 fsync、未确认”无法成立。已确认的最后一帧遭破坏也会产生相同现象；直接截断会静默删除已确认数据。保留明确的 CORRUPTION 契约。既有完整尾帧损坏测试及本轮轮转崩溃测试继续保护这个边界 |
| 2. 异步正文接收拿 slot/registry 阻塞锁 | 属实。先非阻塞尝试取得缓存预算，锁忙时回退到受名额限制的阻塞任务；正文接收只使用取得的原子计数器；取消或超时后阻塞任务继续持有名额，不能反复制造无界工作。测试锁住租户 350 ms，两个 Tokio worker 上的健康检查和计时器仍可推进 |
| 3. 全局 64 名额被慢正文、长维护占满 | 属实。全局执行、正文接收和维护分别可配置；正文接收完成后才申请执行名额。索引创建、compact、check、checkpoint、本地备份及生命周期操作使用独立维护名额。每租户并发限制仍覆盖等待预算、收正文和执行 |
| 4. 2×retention 清空全部租约 | 属实，原有保护确实可能反复使大检查点失效。保留上限改为按租户已计费用量自适应，额外窗口最多取租户磁盘配额的四分之一；只撤销超限且正在阻止回收的租约。有限磁盘仍不能保证任意写入速率和传输速度组合最终追平 |
| 5. 复制导出 reserve_free=0 | 属实。使用 maintenance_reserve_free_bytes，默认 64 MiB；先在刷盘前检查待刷数据与元数据余量，生成副本前检查预计大小，复制和接收过程中持续检查剩余空间 |
| 6. 本地备份无限累计且无删除接口 | 属实。本地备份每租户最多 64 份，总文件字节受 max_local_backup_bytes（默认 1 GiB）及租户磁盘配额的较小值约束，保留物理空闲余量。新增本租户 admin 的 DELETE /backup/{backup}；创建、删除和本地恢复串行，失败输出尝试清理且仍会计入后续占用 |
| 7. 事务闭包的冷读占着 writer、阻止前序提交确认 | 属实。独立串行事务求值锁与 WAL 发布锁，求值期间释放后者；前一批 fsync 可独立确认。事务求值的存储读取受 query_ms 和 max_scan 约束。CAS 和唯一性仍串行检查，未改成无冲突证明的并发事务 |
| 8. WAL 排在同租户 4096 个读任务后面 | 属实。租户轮询不变，租户内优先处理持久化任务；最多连续八个后给读取一个机会，避免读取饥饿。已运行的 OS I/O 不能被抢占 |
| 9. memtable 轮转期间持 writer 做多次 fsync | 属实。下一份 WAL 在锁外按预期起点准备；并发提交未改变边界时复用已同步的头部，改变时才重写并同步。短锁内切换内存表，Manifest 发布在共享 I/O 调度器内、writer 锁外完成。期间可继续追加，但新事务不得在持久注册完成前确认；失败按 COMMIT_UNKNOWN 隔离 |
| 10. 合并挡住刷盘至写入背压 | 属实。合并每 256 条内部记录检查压力，必要时在该维护任务内插入刷盘后继续合并，当前选中的 SST 保持固定。/compact 仍是强制合并，仍可能重写大量数据；没有改变其 API 语义或承诺硬尾延迟上限 |
| 11. HTTP 同步建索引、长快照占资源 | 同步等待 READY 和可配置构建快照期限是现有契约。修复其占用普通 HTTP 执行池的影响，保留独立维护并发、构建期限和可恢复 BUILDING 状态。没有把现有返回索引结果的接口改成异步任务接口；构建期间旧版本保留成本仍存在 |
| 12. 节点写屏障内逐一打开冷租户 | 属实。在屏障外预热位置；屏障内只核对缓存/在线位置，不做冷打开。并发打开、维护或目录变化时返回 BUSY，调用方可重试；不以未恢复的猜测位置完成切换 |
| 中 1. 副本整个拷贝期 BUSY、三份空间 | 前半项与当前代码不符：已有下载前及安装前两段有期限排空，网络下载中闸门已释放。重建已有租户时额外复制一份 staging 属实；私有且已验证的 import 目录改用同卷 rename 移交，只需一份新增副本及余量，旧在线目录在完成发布前保留 |
| 中 2. 副本没有指数退避 | 初始化失败已有 100 ms 至 30 s 指数退避；普通日志应用错误和状态请求失败仍是固定间隔，已补上指数退避。健康租户继续推进 |
| 中 3. 追赶每约 10 ms 全量 status/catalog | 属实。后台复用 100 ms 状态响应，同一响应只做一次成功目录协调；日志页继续独立验证实时 head、epoch 和 generation。显式 sync_once 和切换验证仍取新状态 |
| 中 4. 导出锁内 open、pread | 属实。锁内只检查租约及固定路径/范围；open、pread 和编码在锁外进行。释放/过期与在途读取竞争时仍可能明确失败，不在锁外继续提供已失效快照保证 |
| 中 5. switchover 的 30 s 请求超时 | 属实。节点间 promote 请求单独使用 150 s，覆盖服务端 120 s 等待窗口及普通请求余量。网络或不可返回 I/O 仍可能失败；旧主持久 fence 不会自动撤销，重试继续完成切换 |
| 中 6. 事务前缀扫描不计墓碑、GC 反复从头扫 | 属实。普通事务前缀扫描也受物理扫描预算限制；过期队列保存访问键并按物理记录分页推进，墓碑也能推进游标。补录更早的过期任务时回退到必要位置，空队列不会为推进时间持续写 WAL |
| 中 7. flush 预留 mem.bytes×3 | 属实。刷盘与合并均改为元数据余量加实际 SST 输出增量计费，失败保留原 WAL、Manifest 和可重试状态；不是取消磁盘限额 |
| 中 8. 繁忙租户管理操作持续 BUSY | 属实。关闭、删除、配额变更和本地恢复发布前先关闭入口，最多排空一秒；正常短读重叠不再导致无限饥饿。长期嵌入式句柄仍由调用方释放，超时恢复原入口并返回 BUSY |
| 中 9. 无连接限制/写超时 | 属实。独立服务监听器增加连接名额及 socket 写空闲期限；测试覆盖连接占满、长处理器等待和写背压，并确认无操作的 flush 不能刷新写期限。嵌入式 Router 的连接政策仍由宿主提供 |

## 持久化与并发不变量

新 WAL 可以在目录注册发布期间接收数据，但该阶段通过持久化等待状态阻止 group commit 确认新序号。Manifest 发布失败保留恢复所需文件并隔离写入；发布之前崩溃时，原 Manifest 引用的旧 WAL 包含全部已确认事务。对轮转与事务求值交错的情况，事务返回的快照从实际接受该写入的当前视图固定，不能漏掉自己的写入。

合并中的刷盘仅追加 L0 和推进 checkpoint，不改变该次归并固定的输入文件。合并最终以最新视图/Manifest 移除所选输入并保留期间刷出的 L0；旧快照和已确认记录仍可读取。SST 写出、元数据预留、失败清理及实际磁盘计数继续生效。

新 HTTP 正文预算准备及接收共享最多五秒期限。即使客户端放弃，仍在等待磁盘的阻塞任务继续持有全局正文及租户名额，直到任务结束。执行中的存储工作同样保持原有取消后资源所有权，不能仅因 HTTP future 被丢弃就提前释放并发预算。

## 回归覆盖

新增 17 项行为回归，并扩展既有轮转崩溃场景：

- 两个 Tokio worker 中锁住一个租户，健康检查及计时器继续响应；两个租户各持有 32 个慢正文，第三租户仍可执行。
- 同租户持久 I/O 越过读积压且读取不被无限饿死；后续事务求值不阻止前序提交确认。
- 事务快照在并发轮转后仍包含自身已确认写入；轮转等待 I/O 时 writer 可取得；轮转发布前进程中止仍保留已确认数据。
- 事务前缀扫描计入墓碑并拒绝超限未提交工作；过期队列跨多批墓碑推进，并处理补录任务。
- 小磁盘刷盘使用实际输出；合并中插入刷盘并核对原记录及并发内存表记录。
- 本地备份超额被拒、删除后释放容量、恢复及正文不变；删除接口检查角色与租户边界。
- 复制与本地备份因物理余量被拒时不触发源端刷盘、不 poison 写入；较大检查点超过两倍正常日志窗口仍保留传输和追赶能力。
- 管理操作排空交叠短读后完成；连接上限、长处理器不被写期限误杀、带 flush 的写背压超时真实运行验证。

## 验证边界

使用 OrbStack Ubuntu Linux aarch64，构建与原生数据位于 `/var/tmp`，故障脚本单独挂载 256 MiB ext4 loop 卷。测试仅管理自身临时目录、凭证和进程，不修改共享系统盘容量；结束后停止进程并卸载测试卷。EIO 为限定测试 WAL 路径的 syscall 注入，不能代表真实设备掉电或内核写回错误的全部行为。

有限日志窗口、真实磁盘不足、长时间保留的嵌入式 Arc、不可返回的 OS I/O 以及同步索引构建的旧版本成本仍是明确边界。没有将本轮验证扩张成默认规模、50 GB 跨机房、长周期生产运行或 macOS/S3 实际服务的通过结论。
