## 容量及恢复边界

每租户持久任务数量最多 `min(64, ceil(max_jobs / 2))`；每租户暂存准入为 `max(max_backup_bytes, max_staging_bytes / 2)`，包括活跃预留和已有保留工作区。全局限制继续生效，配置本身仅可容纳一份备份时不能承诺并发。恢复下载失败不再永久留存，但创建失败的同 ID 重试仍依赖本地检查点。升级前已占满全局上限的旧创建任务需显式 forget，不能自动删除用户可能仍要重试的备份。实际磁盘错误、清理失败和容量不足仍需运维处理，这些限制不是文件系统硬隔离或性能 SLA。

prune 的内存不再随总引用数增长，但大库存会重复读取保留清单，增加网络 I/O；仍受已有任务截止时间限制。损坏清单继续拒绝 GC，不会将其视为空引用。列表接口仍保留 4096 份响应限制，prune 使用独立流式路径解除超限。远端备份保留是独立契约，不随在线租户删除自动清空。

本轮防止删除集合后的新孤儿写入；未新增对历史版本已经产生、且 GC 任务已结束的孤儿索引进行全库扫描修复的工具。

验证环境为 OrbStack Ubuntu AArch64，数据与 Cargo 产物放在 Linux `/var/tmp`。远端备份使用 OpenDAL fs 后端，并通过真实目录阻断制造上传失败；覆盖真实 HTTP 双节点切换、磁盘清单/对象操作、Store 重启及 OTLP 测试收集器。不代表真实 S3、设备断电或长期生产压力资格验证。
