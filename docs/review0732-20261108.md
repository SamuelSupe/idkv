# 0732ffd 复查与修复（2026-11-08）

基线为 `0732ffd18daedc88c6a602db0a2612c4ca961693`。本轮逐项核对报告，并在 OrbStack Ubuntu AArch64 运行回归；不重新审查 5600a4e 的缓存设计。下表区分修复和保留的契约，不能把原报告的每条推断都当作已复现故障。

## 高优先级

| 报告 | 结论与处理 | 证据 |
|---|---|---|
| 大备份可创建、无法恢复 | 属实。Restore/Import 单租户暂存上限覆盖 `2×max_backup_bytes+1 MiB`，Create 仍用原隔离额度，全局总额继续生效。默认全局额度补上 1 MiB 元数据余量。 | 原版拒绝 60 GiB 的恢复预留；修复版接受 60/100 GiB 预留并继续拒绝超过剩余全局容量的任务。此处验证真实准入代码，不声称实际传输了 100 GiB。已有 fs 后端备份、校验、恢复测试验证端到端数据。 |
| WAL 截尾可能丢已确认帧并复用序号 | 属实，改变恢复策略。CRC 或魔数损坏一律 CORRUPTION，保留原 WAL 及 `.corrupt` 硬链接，记录 ERROR 和进程计数。只有水位外的长度不完整尾帧仍可恢复，恢复前同样保留原件。 | 基线矩阵测试复现静默成功。修复后验证 36 组合；独立子进程完成两次已确认写入后异常退出，损坏第一帧且保留后一帧，连续重启均拒绝打开/发布复制位置，原字节不变。以测试保存的可信图像修复后，两次确认 revision 均一致，下一次写入序号严格更大。 |

WAL-SYNC 不是逐提交确认水位，按“一次组提交窗口”限制丢弃仍无法证明被删帧未确认，因此不采用该启发式。新策略通过禁止损坏源继续写入阻断本次报告中的分叉路径，没有新增帧级哈希链；若 0732ffd 已经截尾并覆盖原件，新版无法仅凭序号识别旧分叉或找回已丢字节。应核对备份、从库及业务确认记录，选定权威历史后完整重建受影响副本。合法不完整长度仍不能排除介质丢失已持久尾部的极端情况，不能将进程故障注入等同真实设备认证。

## 中优先级

| 报告 | 结论与处理 |
|---|---|
| 安装退避期间一次 502 就丢下载 | 属实。保留副本，暂态探测错误短暂重试；致命历史/日志错误退出。扩展原真实双节点场景，在首次排空超时后的退避期间返回 502，之后安装完成且快照请求数不增加，其他租户继续推进，核对正文和 revision。 |
| 每 29 秒一字节无限占 cycle | 属实。整个请求另限 120 秒，节点间 promote 为 180 秒，仍保留连接/响应头/单块停滞期限。真实 TCP 滴流在缩短的同一路径期限内失败并释放 cycle；原 32 秒持续响应测试保留。 |
| 未配置 retention 的回执永久保留、r 映射不清理 | 回执永久保留是既有“无 TTL”幂等契约，不能自动清掉后允许旧请求重做。文档明确必须显式启用 retention。无回执的集合删除不创建映射；启用策略后分页核对并删除无回执的名称映射，页间有新事务则重新扫描。回归覆盖扫描游标后方新插入回执，且清空后不产生空转 WAL。 |
| 隔离租户删不掉、切换一直要求重启、原因缺失 | 缺目录时 offline_lock 失败属实，现可显式删除、释放名称。启动原已写 stderr 日志；本轮增加复制 unavailable 的具体原因和 UUID。计划切换仍拒绝未解决的 journal，错误说明应修复或显式删除，不能忽略可能有数据的租户。回归核对健康租户读写、故障原因、删除及同名重建。 |
| 副本缩配额先检查再 flush | 属实且在基线运行复现。200 次覆盖写留下超过 24 MiB WAL，主端 flush 后可缩容、副本被拒。修复后磁盘单独缩容也先用旧额度 flush，再计算占用并发布，最后核对已确认文档与 revision。 |
| CLOCK 缺失时坏/超配置清单阻止新备份 | 属实。每次服务启动后首次创建都核对远端，损坏或缺失的已完成清单记录诊断但不参与时钟计算；旧清单元数据读取不受调低后的备份数据大小上限约束。prune 仍不猜测坏清单引用，新增显式 Delete 任务和 admin HTTP 入口处理坏清单，再执行 prune。回归包含损坏、清单缺失及超配置旧备份，核对新备份创建、拒绝不安全 prune、显式删除、保留最新及完整 verify。 |
| ENOSPC 只读返回旧视图/正常 404 | 属实。诊断实例保留，但普通快照/文档/查询返回 RECOVERY_REQUIRED（503），不再返回容易被当作当前状态的旧数据；释放空间后 close/reopen。回归核对失败时原 WAL 不变，恢复后数据可见。 |

## 低优先级

| 报告 | 结论与处理 |
|---|---|
| 退避后 begin_replica_install 的 BUSY 无限重试 | 属实。整个已下载安装等待（含探测和取得闸门）限 90 秒；每次排空 10 秒、两次排空超时退出。网络探测在排空闸门之外进行。OS 内已进入的不可中断 I/O 不受异步计时强制中断。 |
| 错误白名单及 message 丢弃 | 补全 CONFLICT、READ_ONLY 等非暂态码，保留最多 512 字符、去控制字符的对端诊断；未知码/HTML 仍映射不可用。回归覆盖 502、未知码、CONFLICT、READ_ONLY。 |
| token 513/514、owner/硬链接及非原子轮换 | 明确 513 文件字节上限、514 检测读取；检查当前有效 owner 和单硬链接。轮换仍要求原子替换；非原子改写期间读取错误归为暂态不可用，不能保证半写入文件可用。回归覆盖硬链接拒绝、权限、大小及有效轮换。 |
| 缩配额只留 4 KiB | 改为在前台 80% 空间内留出 `max_batch_bytes+4096`，默认约 16 MiB。以后新写入仍可能消耗余量，不承诺任何时刻任意规模删除都成功。 |
| 迁移堵住到期清理 | 新增迁移记录继续受前台额度限制；失败时另事务尝试已有到期清理，已到期且未登记期限的旧回执可直接删除。旧发布版本的引用迁移未完成时仍保守保留，可能仍需整理/扩容。回归核对迁移未占维护余量、已有到期记录删除、业务记录保持不变，以及被引用迁移挡住时不制造空转 WAL。 |
| 已有 CLOCK 不核对远端、未来值无上界 | 每进程首次为租户创建时核对，支持旧盘镜像的较低有效水位；超过墙钟 366 天的清单视为异常，本地异常时钟重建。回归包含有效旧水位、远端较新备份、重启、极端未来值及 prune。仓库仍只支持一个 Store 写入者。 |
| 本地 rename 后 sync 失败不知 backup ID | 返回 BACKUP_COMMIT_UNKNOWN 并携带 UUID；failpoint 验证可以据此找到并显式删除该副本，在线确认数据不变。 |

| history 拒绝前计入读统计 | 保留。指标表示已经发生的查询/Lookup 工作，不是成功返回计数；该次查询确实消耗 I/O。文档明确用 HTTP 成功/错误指标区分结果，不从用户 JSON 推导统计。 |
