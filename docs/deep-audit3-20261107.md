# 第三轮稳定性审查（2026-11-07）

本轮检查基线 `81c46c6bcff79f04fd08ee13cdf922dbaa72a40f`，确认两项重要可用性缺陷。仅新增审查脚本、运行证据与本文，未修改产品代码，未提交或推送。

## 1. 高优先级：正常刷盘使已确认数据持续不可读

**合法配置**：全局内存 64 MiB、租户内存 8 MiB、memtable 1 MiB、cache 0，其他采用默认值，默认允许最大 1 MiB 文档。没有缩容、并发压力或故障注入。

通过 HTTP 创建集合并成功写入一条带 700 KiB payload 的文档，收到 `rev=2`。随后 11 次 Get 返回完整内容及正确修订号；约 91.8 ms 后后台维护正常刷盘，此后的 Get 返回 HTTP 429 / `RESOURCE_EXHAUSTED: tenant memory budget exhausted`。没有发送 checkpoint 或 compact 请求。此时租户 active、maintenance_error 为空、已记账内存仅 2,212 字节，flush_bytes=3,447，排除了仍有大量驻留内存的解释。

另一个确定性对照使用 memtable 4 MiB 保持数据先留在内存表，成功写入和读取后调用 checkpoint，checkpoint 成功，而 Get 与 check 立即失败。中止并重启服务后仍失败；仅把该租户内存提高到 16 MiB，完整内容和 `_rev` 与刷盘前完全相同。这是持续读取不可用，未观察到物理数据丢失。

**根因**：`src/storage/sst.rs:649` 的块解码先按 `raw_len * 12 + frame_len + 1024` 预留内存。实际原始数据块为 716,940 字节，对应预留 8,607,268 字节，单块就超过 8,388,608 字节配额。写入准入和 `Options::supports_quota` 没有保证已接受记录在 SST 形态下也可读取；缓存淘汰、空闲关闭和重启都无法修复单次预留本身超过总配额的问题。Get、需要该正文块的更新/删除及完整存储校验都会受到影响。

**建议**：统一写入、刷盘和读取的最小工作内存契约。优先根据真实的块解码分配收紧预留并保持正确计费；无法在指定配额下可靠读取的单条记录应在确认写入前被拒绝。增加“同配额下写入→后台刷盘→读取→重开”的行为回归，不只验证写入及 memtable 读取。

证据：[后台自动刷盘结果](../bench-results/deep-audit3-20261107/background-result.json)、[重启/配额恢复对照](../bench-results/deep-audit3-20261107/memory-result.json)。

## 2. 中高优先级：复制初始化错误使用节点默认配额

主从节点默认租户配额均为 8 MiB、全局 64 MiB、memtable 1 MiB、cache 0。主库创建租户并将其实际配额提高到 16 MiB，成功写入同样的 700 KiB 文档，checkpoint、Get、check 全部成功，再启动空从库。

约 1.08 秒内出现 4 次初始化尝试、4 次失败，错误均为 `tenant memory budget exhausted`，从库没有安装此租户。实际远端租户配额 16 MiB 已通过复制配额兼容性检查。保持主库及其数据不变，仅将从库配置中的默认租户配额改成 16 MiB 并重启，从库一次初始化成功，服务就绪后约 33.3 ms 追平至 seq 2，完整正文和修订号核对一致。

**根因**：`src/replication/bootstrap.rs:147` 用 `Store::import_context()` 建立临时校验预算，而 `src/tenant/manager.rs:339` 为它创建的 Counter 固定来自节点 `options.tenant_memory_bytes`。传给 Engine 的 TenantInfo 虽然携带远端真实配额，预算 Counter 仍被错误限制为默认值。因此提升租户配额不能帮助检查点预校验，退避重试也不会改变这个限制。租户数据超过默认预算而未超过实际配额时，副本初始化可能持续失败。

**建议**：复制检查点校验使用已验证的远端租户实际配额，并继续受同一个节点全局预算约束；已有租户重建还需对同一租户仍持有的资源统一计费。不要直接改变灾备 import 采用目标默认配额的既有契约。增加“实际租户配额大于节点默认值”的原生主从初始化回归。

证据：[主库健康、从库连续失败及修改默认值后的对照](../bench-results/deep-audit3-20261107/memory-result.json)。
