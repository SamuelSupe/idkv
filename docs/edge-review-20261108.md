# 低优先级与边界场景复查（2026-11-08）

> 历史记录：其中自动容忍 CRC/魔数损坏、ENOSPC 提供旧前缀读取及暂存预算等结论已由 [0732ffd 复查](review0732-20261108.md) 修订。

基线为 main `5600a4e`，工作区还包含前两轮尚未提交的 WAL 尾部与子系统修复。本报告只记录本轮新增清单的核实、修复与验证；不是生产运行或真实断电认证。

## 逐项结论

| 项目 | 核实与处理 |
|---|---|
| 检查点先 publish 后同步 SST 目录 | 存在。先 fsync SST 目录，再发布 Manifest；增加发布前崩溃点。 |

## 运行验证

使用 OrbStack Ubuntu AArch64；测试数据与构建缓存位于 Linux `/var/tmp`。最终完整套件采用 `--test-threads=1` 隔离不同测试的进程级状态，各并发场景内部仍使用真实多线程、异步 HTTP 和独立进程。没有在宿主机安装额外测试框架。

新增回归覆盖：唯一值批次交换及真实 Lookup、130 条跨页在线追赶与已确认 revision、集合删除/GC/重建/重启后回执不重做、缩短策略后发布集合回收仍保留长 token 回执、危险缩配额、损坏的单租户 journal、长达 32 秒且持续推进的 TCP 响应、502 HTML、未知远端码、token 轮换和权限、从库误切换与旧主幂等重试、上传 abort、任务上限下调、备份时间回退、checkpoint 发布前崩溃、ENOSPC 只读前缀及后续恢复。

扩展现有回归核对：排空超过 10 秒后仍只下载一次、开放读服务并重试安装；restore 发布失败后其他租户发布不覆盖意图；保留策略迁移不占维护余量而删除仍能推进；not-ready 传播期间继续接收业务；停止监听先于等待长响应。

旧版基线与修复版使用相同的业务断言。基线中批次交换、回执重做、危险缩配额、降低任务上限均运行失败；日志在 `bench-results/edge-review-20261108/baseline.log`。备份回拨测试使用带有效完成标记的“时间在未来”的已有备份，再创建新备份并重启、prune、verify，不修改主机时钟。

最终完整套件 **259 项通过、0 项失败**，较前轮新增 16 项回归；Clippy（`-D warnings`）、格式和差异检查通过。最后仅调整测试 fixture 的 3 项检查另行复验通过。测试和静态检查结果见同目录 `summary.json`、`tests.log`、`clippy.log`，最终源码指纹见 `source-provenance.json`。

## 验证范围

所有故障注入、文件系统备份及 TCP 行为测试均在本机 OrbStack 完成。没有真实块设备掉电、S3 服务端 multipart 故障或生产长时间压测；checkpoint 崩溃点和 WAL ENOSPC 注入验证的是程序状态转换，不能代替硬件持久性验证。普通读的可见性收紧为已证明持久前缀是有意行为变化；只读恢复仍可能暂时看不到水位之后的已确认写入，释放空间后可恢复，不能把只读位置用于升主。

并行运行的原日志保存在 `tests-parallel.log`。迁移分页测试先启用策略、再停止后台 worker，有机会在插入合成旧数据之前被后台推进；已调整为先停 worker 再建立场景。索引管理测试在 READY 后立即创建 Lookup，仍可能遇到契约允许的 L0 背压；已按期限重试，继续核对全部已确认文档与 Lookup。

一次并行崩溃测试中，关闭 Store 后的立即重开返回 BUSY，未捕获该次的锁持有进程，不能声称已确定根因。独立的 `lock-inheritance-probe.rs` 实验确认：子进程在 exec 前继承的文件描述符可以在父进程关闭 Store 后继续持有根锁；子进程退出后重开成功，已确认 revision 不变（见同名 `.log`）。没有因此弱化 Store 独占锁或在生产路径吞掉 BUSY。

该重开测试又隔离连续运行 20 次，全部通过，日志为 `isolated-reopen.log`；这降低了稳定复现的可能性，但不消除上述未确定根因的记录。
