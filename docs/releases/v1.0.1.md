# idkv 1.0.1

**Released November 9, 2026.** This patch improves WAL commit scheduling, indexed writes, and replication log transfer.

## Changes

- Idle tenants start WAL fsync immediately. Under contention, `wal_group_window_us` controls the collection window. The default is `1000 µs`. A value of `0` skips the deliberate wait, and acknowledgements still follow durable WAL sync.
- The engine packs WAL frames outside the publication lock and reuses staged index definitions. A batch with one `Put` or `Delete` and revision checks uses the unique index fast path. Multiple mutations still support atomic unique value swaps.
- Updated peers can stream binary WAL frames via weighted `Accept` negotiation. JSON remains the default and supports mixed-version replication. Both encodings enforce a 96 MiB response limit, and the binary decoder validates reserved cursor bytes.
- HTTP takes over the global charge for an in-flight binary frame and releases the tenant charge. The regression holds an output frame while testing both the former tenant charge and the current write path.

## Upgrade from 1.0.0

The release uses registry 6, replication protocol 4, and WAL/SST format 1. New peers accept JSON from 1.0.0, and old peers receive JSON from 1.0.1. Set `wal_group_window_us` only on nodes running 1.0.1. Verify a backup and upgrade each node's server and offline tools together.

## Validation

- OrbStack Ubuntu ARM64 passed 298 source tests with failpoints enabled, including the slow-frame quota regression. The separate million-row qualification was skipped. Clippy and formatting checks passed.
- Both Linux production builds passed the ELF and static-loading checks, tool version and help checks, and OpenAPI comparison. HTTP, DSL, identity, retention, filesystem backup, offline import and archived WAL repair passed on both targets. x86_64 execution used emulation on the ARM64 host.
- An ARM64/x86_64 pair and a 1.0.1/1.0.0 pair each passed checkpoint initialization, 4,000 document updates, replica restart and WAL resume, and planned switchover in both directions. Both pairs ran over loopback with a 4 MiB demo memtable.
- WAL write and sync fault injection with a zero collection window preserved acknowledged data after restart and verified operation-ID retries.
