# 复制导出生命周期修复（2026-11-06）

此文记录 31851b6 的历史验证。后续发现的不确定提交切换分叉、活动句柄重复初始化及相关修复，见 [复制安全修复](replication-safety-20261106.md)。本报告的旧构建及测量不能替代后续安全修复。

以 63c92c1488a34dff22dfe060eb4cb22383de9b9b 为基点复核，报告的前三项均属实。版本仍为 0.10.1，持久格式和复制协议 3 不变；部署需区分构建哈希。

## 处理结果

| 问题 | 修复 |
|---|---|
| 准备及传输一小时硬期限 | 删除总时长上限。准备工作持有的 WAL pin 由字节窗口兜底，完成后按传输活动续期 5 分钟；持续有活动的大检查点可超过一小时。空闲过期及超字节窗口失效的租约仍不能复活。 |
| 生成检查点持有 exports 锁 | 锁内只预留“正在生成”的身份，锁外打开租户、复制和哈希，完成/失败后在短锁内发布结果。重复创建返回 BUSY，其他租户日志请求不再因长生成任务拿不到状态锁而跳过续期。 |
| 日志请求同步递归删除目录 | 交还槽位时只把目录加入清理队列。后台在锁外删除并同步目录，失败保留路径并重试、记录错误；有效日志页不因清理失败而报错。失败的准备任务和主动 release 同样走此路径。 |
| 难以发现反复初始化 | status 与 Prometheus 增加初始化尝试、失败和 LOG_GONE 重建次数。只计实际启动任务，不计在途任务的重复调度；重建是尝试数，不是成功数。 |

没有增加新的配置项或依赖。两倍 log_retention_bytes 保护已刷盘保留 WAL，仍可能使持续高写入、慢传输副本反复初始化；需要扩大窗口或降低写入速率。flush/compaction 共享维护锁、跨主体共享游标总额仍保留，不能据此宣称尾延迟隔离或分页公平。配置、资源边界与告警表达式见 [复制文档](replication.md)及[遥测文档](telemetry.md)。

## 回归验证

在 OrbStack 原生 Linux AArch64、普通用户 livesite、Rust 1.90 下，完整 **134 项测试**、全目标 Clippy（failpoints，-D warnings）和发布构建通过，见 [validation.log](../bench-results/export-lifecycle-20261106/validation.log)。首次 Clippy 拒绝测试中非八进制权限字面量，改为 0o000 后重新执行完整验证；过程保留于 validation-first.log。format-read-first.log 记录共享目录短暂读取到不完整文件的格式检查失败，后续主机和 Linux 内容核对完整后重跑通过。

- 使用可控 Instant 验证两小时准备后仍可续期，再每四分钟推进租约四小时，最后空闲超过五分钟必须失效且不能复活；没有等待六小时的真实墙钟试验。
- 使用现有 I/O 调度器冻结真实 SST 检查点复制，验证另一个租户日志请求在释放阻塞前完成，重复快照请求立即 BUSY，释放后准备完成。
- 真实权限故障验证清理失败不改变日志结果，失败路径留在队列，修复权限后可重试删除；另测准备失败交还生成占位。
- 扩展原有日志窗口过期重建回归，核对重建前后完整正文及 _rev，并通过真实 HTTP /metrics 检查三个外部计数器，避免另建重复的重建场景。
- 原有持续写入超窗失效及未记住 release ID 的回归保留，目录断言改为等待后台清理，仍在清理前验证另一租户能取得槽位。
